# 竞赛路线与 OpenSpec 变更顺序

阶段、授权、已通过身份及下一步统一见 [REVIEW_STATE](../reviews/REVIEW_STATE.md)。当前增量是 `bootstrap-baseline` 的真实 B 运行准备（provider profile、受控传输与预算预检），实际模型 API、真实 C 尝试与官方判分继续暂停。实现分工按 [当前工作流](../docs/luna-subagent-workflow.md)，不操作 Antigravity。

本文件用于协调变更顺序；具体行为契约写入各变更的 `specs/`，实现取舍写入 `design.md`。尚未决定的 Agent 改进策略不提前写成已冻结需求。

所有阶段同时遵循 [学习约定与进度](../docs/learning-agreement.md)：解释当前设计，结合真实材料/源码/轨迹教学，用简短理解问题反馈，并记录下一步。教学是协作要求，不改变比赛的自主评测规则，也不把完成课程设为开发前置条件。

2026-10-21 的 [开发讨论](../docs/development-discussion-2026-10-21.md) 补充了官方能力与自有实现的分工、已核对的工具调用示例及各阶段证据。它是规划说明，不代表模型、harness 或改进策略已经冻结，也未恢复实现。

## 阶段 0：理解官方任务（本轮已完成只读拆解）

- 先看 [头痛新转诊任务拆解](../docs/task-walkthrough-pa-t018.md)：输入、静态工具、示意流程、环境限制、评分来源和未知项。
- 本阶段核对官方输入、8 类 30 个静态工具及基础超时；后续实时接入的证据另见 A 审核，不由静态拆解推断。
- 不提供隐藏答案，不凭静态说明填写 task reward，不把单题开发案例当作未见验收集。

## 阶段 1：可信的单任务接入与开发执行

沿用 `changes/bootstrap-baseline/`，不另建重复的基线实现任务。

- 规划任务固定为 `pa_t018_t018_o001_p01_new_referral_provider`，代码和数据分别固定版本。
- 按 D0/A/B/C 核对容器开发环境、角色工具和单任务入口；参赛模型与官方参考 runner 的组合仍是待实测候选，凭据的实际可用性未验证。首轮模型工具接入和一次任务尝试共 5 元已由用户确定，写代码费用另记；预算选择没有恢复付费运行。
- 用户暂缓本地 Anthropic 判分，先验证离线检查、真实工具接入与无评分执行，保留轨迹、版本、状态回读与可信资源记录。具体无评分入口须验证，不能捏造 CLI 参数。
- 官方判分保留为暂缓项；reward 为 null，不能宣称任务已通过或产生竞赛通过率。部分 Claude 模拟对话同样需要单独检查依赖。
- 以后若执行官方判分，保留原版 reward 和 scorecard；有效 0 分也是真实测量，不能宣称解决任务。详见 [开发准备](../docs/development-preparation-2026-10-21.md)。
- 每次恢复按当前审核身份增量核对差异，历史未通过报告只作为对应缺陷的证据，不覆盖后续独立验收。
- B 离线探针用合成响应和合成工具检验请求/历史、关联、预算与失败处理；其通过不代替选定 provider/官方 runner 中的真实连续往返。接入层离线开发见 [设计记录](changes/bootstrap-baseline/design.md#模型与官方-runner-接入层本轮设计)，真实 B/C 仍需另行恢复和验证。

## 阶段 2：根据实际执行证据提出 Agent 改进变更

真实执行后，再决定改模型、规则查阅、工具选择、材料生成或流程控制中的哪一项。工具错误、漏操作、超时等工程问题可以先依据轨迹修复；没有官方分数时，只报告工程诊断，不声称提升了官方成功率。每轮提出独立、可验证的行为变更，不预选网页、编排框架、多 Agent 数量或检索架构。

可参考 [执行循环设计讨论](../docs/agent-loop-discussion-2026-10-21.md) 中的模型/程序分工、运行状态和结束检查候选。这些是待验证的设计方向，不提前当作已实现能力，也不扩大首个 bootstrap 接入变更的实现范围。

改进应可用于同类新任务，不硬编码任务 ID 对应的答案、终态、表单值或文档产物。对照运行固定任务、模型和可比预算；更换模型时单独记录变量。

## 阶段 3：跨领域、小批量与必要并发

逐步纳入医院侧、保险方和照护管理的代表任务。批量与并发是评测组织方式，不等于为每道题写专用 Agent。任务清单和调用数量依据实际资源与预算决定，不把全量 75 题当作参赛资格条件。

## 阶段 4：冻结可复现参赛材料

按 Kaggle 当前 Rules 准备 Writeup、私有可运行程序包和 IEEE 双栏技术报告。模型、接口、提示词、配置和依赖身份可复查，公开实验结果对应真实官方证据。受限手册和凭据不进入提交包。

最终排名由主办方使用冻结系统在私有任务上的评测决定。独立 evidence leaderboard 和完整公开审计包为当前规则注明的可选项。规则及提交流程在交付前复核。
