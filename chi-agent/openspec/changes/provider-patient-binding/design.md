# N：患者确认与绑定设计

## 范围与实验

基线为已合并 PR #17 的 `2b29a69dd9628586daa9481b11af6b8223b0b079`，工作分支 `codex/patient-identity-binding`。唯一实现代理继续 gpt-6.1-terra/high，主代理规格/独立审核/真实验证/GitHub。开发授权沿用真实 DeepSeek、多次本地尝试、record_only/null cap；未知用量阻挡接续，Claude/F.5 暂停。

本轮只改变患者确认/绑定机制及其必要的通用工具说明、确认提示和角色输出边界。官方 base system prompt、participant DeepSeek profile、thinking/high、主业务每次输出 8192、总 provider 请求上限 30、镜像/锁/Python 3.12、资源和 reviewer 配置保持原值。确认子请求也占这 30 次，SDK 主循环 turns 与总 provider 请求数分别记录。新确认提示、工具协议和来源/参数进入源码身份；不是声称提示未改变的实验。

真实回归复用 M 冻结的 t013/t019，资源不重新下载，均已成为开发题，不称未见泛化证据。每个新 attempt 用新世界、独立 run-id 和同一旧累计账目；独立审核后 rebind/new B，再各一次 C/完整终态/确定性部分检查/DeepSeek 开发评审。工程修复需要新源码审核/B，保留此前失败，不自动重试。

## 模型选择与程序门禁

新增通用患者确认工具。输入包含候选选择及可追溯公开依据；模型必须先查完整候选名单和有关 chart，不能把默认一页或第一条当成充分匹配。只从真实成功的 provider MCP 查询构建 observation registry，记录 call-id、工具/参数、患者、内容 hash 与可检索原文；不把模型自报、任意 workspace 文本、fixtures 或未发生的查询作为可信来源。完整 roster 的 total/items 必须可核验，缺页、重复/冲突 ID、失败/不完整 chart 拒绝作完整证据。

确认使用同一个已配置 AsyncOpenAI client，在既有 GuardedTransport/RealDevelopmentJournal 下发起有限的无工具 JSON 请求；不另建计费栈、不换模型。独立上下文包含完整公开 instruction、完整精简 roster 和已观察的有关 chart，而不是模型挑选的一个有利片段。最多两次显式确认；每次先记录 purpose、提示/材料 hash 和尝试，再请求；格式或语义不完备仍结算费用，不自动重试。

响应严格区分唯一匹配、需更多观察、歧义和不匹配，保留未观察的可能候选。唯一匹配必须与申请绑定的选择一致，必要区分事实有当前公开 instruction 和对应真实 chart 的原文/指针依据；引用、患者映射、完整性、候选集合与唯一性由程序验证。不能从“引用存在”推断自然语言已被确定性理解：语义确认仍是同 provider 的模型判断，可能有偏；缺材料、未解决候选、矛盾或无法判定时不得绑定。

付费确认前，完整**未过滤** roster 中与待确认者同 sex、DOB 年相差不超过 1 的年龄近邻，必须都有真实完整 chart；否则返回缺少观察的 ID，不消耗两次语义确认机会。过滤后 total=items 不是全候选覆盖，无效 DOB/sex、重复或冲突身份拒绝。该 cohort 只强制相似候选比较，不等于穷尽语义候选；确认器仍看全 roster，其他未见 chart 的候选若无法排除必须返回 unknown。紧凑响应覆盖每个 roster ID 的匹配状态，选中者给出原文引用；其余候选的语义排除仍是模型判断，不冒充确定性证明。

首轮真实回归暴露了 v1 只说“每个 candidate chart”而模型仅返回已见病例的协议歧义。修复采用明确的三个 ID 数组分区（匹配/不匹配/未知），输入显式提供完整 required_candidate_ids 与 expected_count；程序验证每个 ID 的类型、无重复/交集、并集恰等于完整 roster，再判断 unknown、唯一匹配和真实引文。响应结构错误、覆盖不足、未知候选、选择不一致、引用不成立分别返回 safe reason 与有界的数量/公开 ID 诊断，不能只给笼统 invalid。另一患者被建议为匹配者时不自动绑定，仍需主模型显式选择和确认。此项只修协议/反馈，不改变模型、输出或轮数，也不放宽不真实引用。

第二次真实回归的确认请求在 8192 生成 tokens 后校验失败，全部用量已结算；旧日志未留 finish_reason，不能断言网络故障或确切截断原因。N-R2 撤销“确认器与业务共享同一单次输出上限”的初始假设：仅 K C 由源代码构造、持锁的无工具确认请求采用 32768，主业务/B/J/正式入口仍 8192（B 自身更低上限保留），总 30 次/最多两次确认不变。沿用同一 client/transport/journal，预留、usage 上界和 K pending 读取校验均按可信角色选择；角色不接受模型参数或任意 HTTP 字段指定。确认请求还须精确满足固定提示、模型、消息结构、JSON 格式和思考参数；不能全局放宽 profile。32768 与现有本地评审角色相同，可能增加费用，全部显式计入旧累计账目。

确认响应先持久结算可信 usage 及安全元数据（round、角色、finish_reason、content_present、请求身份），再处理内容。已知 usage 的 length、空内容或格式错误返回明确 refusal，保持未绑定；只有主模型显式再次调用才占第二次机会，不在工具内重试。该已知不完整响应不伪装成 ConnectionError 或未知副作用。HTTP/取消/缺 usage 导致未知用量时停止且不清已有 pending；已经结算后取消仍停止，不把已知用量倒退成未知。未知工具效果也停止，不伪造财务 pending。响应元数据或结算持久化失败不得继续。aggregate 清 pending 前须已有可追溯的逐请求结算证据，崩溃不能造成无凭据放行。

原版 oversize wrapper 可能截断 MCP 输出并给出当前文件工具不能读取的路径。监控层完整结果与主模型已见内容须明确区分；可以提供 registry 范围内、有界、只读的 observation 回读工具/回执，不扩大任意文件权限。不得让主模型伪称读过不可见内容；确认器使用的完整内容及返回的引用都记录来源。

## 副作用边界

K 自主 C 默认启用该机制，无“校验失败后无门禁继续”的回退。J 历史路径与正式 G/H 入口不在本轮迁移范围。确认只能作为单独一个工具调用；与其他读/写同批、两个并发确认、同批读取尚未返回即作为证据、未知/新工具均拒绝。已确认前只允许明确列出的公开只读操作和证据回读；名称像查询但实际写业务状态的工具按真实行为分类。

同一共享锁保护确认和真实副作用前检查/派发/结果登记。MCP 最终执行边界和 local workspace 写/edit 都必须受控；先校验整批已知实体关系，再在实际派发时复验，不能只验证 JSON schema。被门禁拒绝且尚未调用后端的操作返回明确、可审计的 refusal，不伪装成未知业务效果；已经派发但结果未知或身份不一致则封锁后续写入并保留失败，不重试。

绑定后：create_from_order.patient_id 必须是绑定者，source_order_id 由该患者真实 chart/orders 证明归属；创建响应的 patient/case/service_request 交叉一致后才注册 case→patient/order。其他病例由成功 get_case 观察证明，不能信任猜测 ID。form/document/bundle/request/message/p2p 等按固定公开 schema 和已观察关系验证，模板 form ID 可以跨病例复用，须验证 (case, form) 配对，不能错误地当成全局患者 ID。无法证明归属或实体冲突拒绝，不以一次正确检查放开整轮。

workspace 写/edit 只限已证明属于绑定患者的 case/provider|shared 路径，保留既有路径/链接/PDF 边界。绑定后不静默切换患者；任何已发生或不确定的副作用后都不得重绑。临床内容和表单结论仍由模型负责，本机制不等于逐句医学真实性裁决。

## 核算、失败与证据

确认请求保留 request purpose、材料/提示 hash、严格解析结果、拒绝/绑定事件及与逐请求 settlement 的联系，落在原 run journal/本地原始证据，不向 GitHub 上传原文。成功后才落绑定状态。HTTP、取消、回调或持久化异常导致 pending/未知时，停止整个 trial、保留占用；不得作为普通工具拒绝吞掉后继续调用或清 pending。合成覆盖 CancelledError 和 reserve 后观察/校验异常。阻断发生于后端之前与实际副作用未知分别表示。

完整终态捕获及失败标签沿用 M。独立审核还要检查完整 world：目标患者是否被正确识别，非目标患者新增 service_request/case/submission 等业务写入是否为零，是否正常结束，以及引用和机制本身是否生效；readonly audit 不当成错误业务写入。原版 9 项检查与本地 target rubric 保持原义，不用它们掩盖全世界副作用。

## 验证与交付

合成边界至少包括同年龄/性别/诊断而关键经历不同的候选、未查候选/单页 roster、真实与伪造/跨患者引用、匹配/歧义/矛盾/格式/长度失败、两次确认上限、确认与写入并发、跨患者 order/case/form/doc/路径、伪造或冲突返回、未知工具、取消/未知用量/无重试、旧账与 B 及正式入口回归。所有测试使用自造材料，离线测试不依赖下载任务数据。

固定候选停止后由主代理独立复验，再实际回归。比较 M 与 N 的完整副作用、目标结果、正常结束、工具调用、总请求（含确认）、用量/耗时/费用；仅阻断所有写入并不代表任务能力改善。若真实结果未改善如实报告，不把两道已见题回归写成跨任务已验证。
