## 1. 怎样定义完结

本项目交付一个可独立复现、使用统一冻结配置接收 CHI 三角色公开输入、能保留成功/失败及用量证据的参赛 Agent，并形成规则要求的提交材料。完结分为：

1. **工程及材料完成**：正式配送和支持角色的调用链经过实际验证，独立包能复现，实验与限制可查，报告/运行说明/Writeup 首稿完整，用户完成内部验收。
2. **参赛交付完成**：当前规则已复核，所有必交内容齐备，经用户批准实际发布/私有交付，并取得记录或回执。
3. **官方评测结果**：由主办方产生；未返回时标待评测，不阻塞真实已完成的交付，也不预写 reward。

11/6 目标为冻结候选，11/8 目标为前两项完成；外部条件未满足时只能报告实际达到的层级。三角色工程支持不等于三角色临床通过，局部检查也不等于官方任务成功。不用阶段数量、代码行数或测试数量计算完成百分比。

## 6. Z2：给 Y 原型一个可证伪的去留结论

**离线先做**：核对来源实际进入模型请求、当前/历史容量与失效语义、目标 case 信任边界、长文本/Unicode/字符偏移、不同读取窗口、混合列表返回、同批/fatal/取消。测量需要的材料包括来源选择、片段定位、拒绝原因、额外 token/工具/耗时；不要为了测试方便提高容量或宽松承认引用。

冻结一个最小实验：在两个已见 payer 开发任务上比较 off/shadow，任务、模型/参数、预算、资源和其他提示固定，顺序在运行前决定，每个单元至多一次。shadow 暴露工具造成的变化属于处理条件，不能声称只改变无影响日志。确认 Z1 正式路径是否支持该实验；不为了把开发 observer 送进正式包而扩大接线。

**决策**：

- 来源/引用边界可靠、模型能实际使用、未引入明显业务阻断或不可接受开销，才保留继续开发的理由；两题结果只算探索，不足以证明稳定收益。
- 模型持续无法可靠索引、语义错误仍主导、目标信任不足或收益不明，就保留纯原型/默认关闭，按期推进其他工作。
- 不在本计划中增加生产强制批准/拒绝、语义裁判或新的付费临床评审；若要进入正式默认配置，须另列精确行为变更、独立检查和用户明确决定。11/6 前证据不足则正式配置关闭。

Z2 完成不要求结果正向；要求假设、观察、代价和去留结论可检查。

F1–F7是启动本计划后的建设范围；具体技术接口由DeepSeek细化、Gemini审查，不必逐模块等GPT。自动摘要收费、新purpose/上限或官方环境改动仍需另明确。功能不足时不能以“旧接线能跑”判定本节完成。

沿已有 `go_chi_runtime.py` → 工具契约/MCP → 状态/终态捕获，核对三角色差异：

- provider：患者与目标实体绑定、提交/补证的公开依据、避免影响其他患者、正常结束与业务状态分开。
- payer：公开规则/观察/材料区分，条件必需性不由存在性推断；不预设批准或挂起才是正确结局，不按旧 verdict 倒推答案。
- cm：消息/回调/患者 STOP/轮数与结案、账目/辅助请求/取消/清理，明确开发 Go 患者与官方模拟器差异。

各能力先根据公开任务需求/已有观察说明必要性和不变量，再做最小通用实现并固定候选让Gemini审查。允许新增自有状态、角色工作流、资料定位、上下文管理、完成/失败处理和实验模块，以及必要的runtime/guard/contract/journal接线；新增语义必须版本化并保持旧证据。不得硬编码task ID答案、用隐藏评分文件调参或为凑功能数引入无依据的新框架/医疗规则引擎。

为 Z5 新题补齐通用资源选择、公开元数据校验、角色路径及环境初始化的参数化；下载/依赖仍在 Docker 内固定版本。任务资源登记可以绑定 task ID/hash，但不得携带期望答案或按题分支业务策略；环境初始化需要的隐藏资料只留官方隔离服务，不能作为模型输入或调参依据。不能把扩展为六道新题误写成复制六套 Agent。

同时收敛“支持哪些角色/工具、需要哪些外部依赖、哪些检查适用”的表；未知或未支持的角色/输入在调用前明确拒绝。至少每角色有一条正常与一条关键失败链证据，合成和真实分别标记。

## 8. Z4：有界真实开发实验，修复后及时复审

只有 Z0 外部条件/授权与相关离线候选审核通过后才执行。先冻结实际任务清单和资源 hash，核对清单未误用暂停题、隐藏材料或不同任务版本；具体 task ID 由执行者基于公开索引选择、Gemini 检查，不必再等 GPT 选题。

顺序：三角色各一基线→F1–F6实际采用机制的有界对照→适用的Y两题对照→最多六次问题驱动回归。F1–F6合计最多12次C（六组off/on设计，每组最多两次），不采用或不可独立切换的机制交合成/兼容证据和原因，不伪造单项因果；原基线条件一致时可复用且只计一次。无明确机制假设不为填满次数跑实验。发现问题先离线复现、修复、固定候选、Gemini复审，再安排清单内新attempt，不自动重发原HTTP。

每次保留模型/endpoint/参数、instruction/resource/bundle 身份、调用/工具/用量/各项费用、全局前后终态、影响范围、失败及资源清理。运行成功、业务终态、适用的确定性检查、内容未评、官方未评分别列出。payer 出现不符终态时分析原因，不能一律把拒绝/挂起判错。

六次回归的优先顺序：阻断运行/证据→跨患者副作用→新状态/上下文/完成/恢复不变量→角色协议或状态传播→可解释的通用决策缺陷。无具体问题不消耗预留，不围单题追全绿。

## 9. Z5：固定候选的小规模未见任务检查

Z4 后冻结同一模型、提示、工具、依赖、配置和输出策略；预先选定 **9 题，每角色 3 题**，尽可能覆盖F0不同任务家族，不曾用于调参、源码定制或人工轨迹分析。公开索引选题不等于看过解答；完整人工读过轨迹/反馈的题必须算已见。task ID/资源身份/角色与适用检查清单在运行前存档，不能看结果后替换困难任务。

每题一次、新世界、自主运行。已知的业务失败可继续下一题，除非出现新未知、越界副作用、资源/账/来源损坏或清理不能确认。查看结果后再修改候选时，已运行题全部成为开发题；不得将新候选在旧题的重跑写成独立未见验证。预算和时间不足以换新未见集时，如实保留验证缺口。

报告所有九题的尝试/完成/失败/跳过/阻断分母及角色条件；只汇总定义清楚的工程检查，不把未执行官方判分的题转成 reward=0/1，不从九题推导竞赛成功率或统计稳定性。

## 10. Z6：干净包复现与最终真实启动

**先复现，再按已批准额度实际启动**：

1. 从最终候选导出包，不挂源码 checkout、旧 runs/账本或隐含开发卷；空的本轮状态与日志目录，凭据运行时注入，受限资源由有权限方提供，记录目标架构及实际 Python/锁/镜像。
2. 用固定安装说明供应依赖，复用缓存但验证干净起点；其他架构未验证不得写成跨平台通过。不为了复验无关部分重做 G/H，也不能把旧安装通过替代这次配送检查。
3. 在真实 Harbor 适配路径下每角色最多一次真实模型启动，尽量复用为 Z5 对应题以减少重复。若已符合 Z5 全部条件，同一次运行可同时提供启动与未见证据，次数只算一次，不两次计功。
4. 验证官方 world/外部公开输入/MCP、主模型、日志/trajectory/context、进程退出、状态回收与 owned 资源清理。生产包不含开发操作者、Go 患者 broker、调参轨迹或开发账目。
5. CM 使用开发 Go 患者时只能标“真实 Harbor + 真实 Agent + 开发模拟器”；不能标官方模拟器兼容已实测。官方环境依赖如未具备，用隔离接口检查证明的部分和未完成真实路径单列；关键必需路径未验证，不能写完整正式验收通过。
6. 从新日志检查密钥/受限内容是否意外进入待分发产物；必要 raw logs 留本地，公开结果只用获准摘要。用明确 allowlist 生成交付内容。

F.5 的冻结/演练范围在执行启动时显式纳入，不因历史暂停而从完结清单消失；官方 judge/模拟器付费调用仍按独立决定处理。若当前规则允许无本地官方分数交付，可在清楚列出未评项的条件下提交；若不允许，仍属外部阻断。

### 集成与完成条件

同一工作区同一时段一个写入者。Codex做关键修正时，DeepSeek停止共享实现写入；确需同时工作必须先隔离checkout和结果资源，不默认并发。先做M1/M3建立边界和检查，再安排C3/C4有界修正；C1事实核对优先；C2按用户明确启动的P0–P3实施，M2可独立安排，M4等schema，M5贯穿各包。

每个实际实现PR绑定基线/候选，列范围、真实命令/环境、成功与失败、skip/依赖缺口及未验证项。所有安装/下载/测试/调试在Docker/Python3.12，既有缺anthropic等环境错误不能改成通过，不为本规划新增依赖。只跑与修改相关且能检验边界的检查，发现新风险再扩大；固定候选后独立复验，不能只凭作者自测。

运行代码、包、提示或证据schema发生变化后按现行身份/新B条件处理；本次不创建release/B/新state或真实C，不改变原授权清单。目录搬迁、journal拆分、身份/策略解耦仍需独立设计及回归，不与这些小修或截断功能捆绑。新状态只能写“计划/方案已记录”，不能写“问题已修复/验收通过”。

## 16. 输入侧上下文治理

用户同意保存[输入设计与验收](input-context.md)：补齐实际请求计量/输出预留，保留完整证据并建立版本化活跃视图，优先有来源的资料分段读取，再评估同步、有界摘要及检查点。临床材料不统一首尾截取，摘要不改未知写效果/来源权限/账目。Codex与Harness的参考机制和CHI定制边界在该文档区分；不照搬自动溢出重试。

输入自动摘要的窗口、协议、schema、用途和额度仍待独立冻结。计量/预留与输出恢复按[输出恢复P0–P3](output-recovery.md#7-实现工作包及负责人)推进，实际结果见唯一审核状态及阶段报告；不因计量完成宣称压缩已实现，不恢复任何真实调用。
