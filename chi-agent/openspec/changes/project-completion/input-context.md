## 1. 先补计量覆盖和输出预留

设计初核时 `go_chi_context.measure_request()` 单列 reasoning_chars，但 total_chars 未包含它，也未完整包含历史 tool_calls 参数；total_bytes 未用于估算门禁。这个旧版本发现不证明曾发生实际溢出。C2 将新计量版本定义为完整最终 JSON 字符/UTF-8 字节与真实 wire 字节，分项仅用于组成说明；预算采用明确标识的字节启发式及本次实际输出预留，旧v1证据按旧语义保留。实际验证只查审核状态及其阶段报告。

实现前先登记实际路由/模型/协议的输入与输出容量规则。计量以最终实际发送的请求为对象，覆盖 system、原始 instruction、工具 schema、历史文字、工具名/参数、结果、实际回传的 reasoning、标识/结构开销和适用附件投影；不把服务端不回传的内部推理假作已发送文本。分别保留实际字节数、分项字符数、估算方法/版本、可信 provider 用量及其来源。不得把启发式估算改名为精确 tokenizer。

输出预留随用途和实际请求上限匹配，主循环、continuation、确认、患者及未来摘要分别登记；推理与可见输出是否共用限额由协议核实。若路由采用共享上下文窗口，必须同时留出本次输出与压缩指令/摘要工作空间；具有独立上限的路由按其契约处理。触发阈值、安全余量、摘要上限和最近保留量待覆盖中文/JSON/长参数的测量后冻结，不直接复制 Harness 默认百分比或 token 常量。

验收包括：长中文、长 reasoning、只有大参数而 content 很短的工具调用、多工具 schema、结构开销、不同用途输出预留和坏配置；这些字段增大时预算不能无变化。未知容量/计量失败或最终仍超限时给明确停止原因，不静默发送。

## 2. 完整证据与活跃上下文分别维护

完整证据层持续保存原始请求/响应、工具 observation、失败、usage/费用和历史未知；压缩不得覆盖或删除原日志，不改变 claim/pending/settlement/seal，不以清理或换 root 获得新额度。

活跃上下文是程序构造并验证的派生视图：规范 system/工具契约、原始任务约束、程序保护状态、旧历史摘要及近期完整工具往返。压缩视图具有明确版本，与原历史序号/调用 ID/hash/来源版本建立映射。当前 ToolContract 要求完整回传已接受历史，必须新增明确的版本化视图验证及身份处理；不能靠删校验或接受任意摘要绕过它。

保护状态由已接受的程序事实生成，至少包括任务/角色/实体 ID、已执行动作、最新已核实状态、未决/未知写效果和证据引用。模型摘要可解释关联、计划和缺口，不能自行将 unknown 改成成功/失败、升级业务状态、修改费用或授权下一动作。来源有效不等于临床正确或业务批准。

## 3. 资料增长优先通过有来源的读取控制

优先限制每次资料读取量，按页/段/命中位置获取可定位片段，保留原文回读路径与来源版本。普通重复开发日志可以按明确类型缩减；保单/临床资料不统一采用首尾截取，避免删掉中间的排除、否定、时限和适用条件。

摘要与原始来源区分类型/可信层级，不把模型生成文字登记成新原始 observation。与 Y/来源登记整合时，明确原文曾被观察、当前视图实际包含和当前仍可引用三者的关系；旧 source 被替换或失效后不能借旧摘要重新 current。摘要不得扩大文件/任务/角色权限，也不能引入隐藏 expectations 或 world-only 内容。

若单次新输入本身超限，历史摘要不能解决。首版明确拒绝并说明分段/缩小范围的办法；需要将原始 instruction 外置或改为分段读取时，另行更新其原文校验契约。不能先把超限输入送入摘要模型，也不能截掉用户要求后仍宣称完整接收。

## 4. 首版同步、有界摘要及检查点

概念流程（尚未实现）：构造并验证最终请求 → 计量及输出预留 → 必要时按已批准规则缩减资料投影 → 再计量 → 为可压缩的旧闭合批次取快照 → 生成摘要候选 → 校验 → 保存/采用新视图 → 再走完整发送门禁。

只选取闭合工具批次，保留最近完整往返；未收到结果的工具批次不能拆开。system/工具定义和保护状态由程序重建。历史 reasoning 的保留/省略、摘要检查点能否开始合法新上下文，需要在实际使用的 OpenCode Go chat-completions 协议上验证；Harness 适配器的行为不能直接充当兼容证明。

摘要请求的业务工具执行通道关闭。即使为缓存保留 schemas，也须程序禁止派发并拒绝含工具调用的摘要候选。摘要与来源文字不具有 system/developer 指令权限，不能通过摘要升级原文中的指令。摘要字段覆盖目标、已核实事实及来源、不确定性、已执行动作、缺口、当前工作和下一步；精确状态以保护字段为准。

安装前拒绝：空摘要、输出截断、坏结构/越权字段、工具调用、保护字段冲突、不可解析来源、过期选区/版本、未实际缩小、最终请求仍超限。语法/字段/hash校验只证明机械边界，不能证明摘要全部语义正确。

检查点记录选区/版本、摘要及其 raw output、调用身份/用量、前后测量和失败；安装与持久化要能辨别未开始、候选未采用、已采用及持久化失败。失败时保留旧证据，不把未持久成功的摘要标成可恢复。首版不后台并发摘要，不静默反复摘要。

## 5. 额外调用、输出截断及授权

摘要是独立的额外模型请求，不能隐藏在工具次数或算作免费操作。未来实现要定义用途、request ID、同一 evaluation/attempt 的关联、共享总额及摘要子限额、超时/取消和可信 usage 结算；未采用或失败的摘要调用仍保留实际用量。结果/token 未知遵守既有阻断，不以摘要或换账根恢复准入。本输入文档不预定摘要purpose名称/次数/额度或真实调用授权；输出continuation已由独立方案规定，不受此处摘要待定项混淆。

输入治理与输出截断共用容量和记账基础，输出恢复的首版用途/额度/两种模式见[实施方案](output-recovery.md)，不再从本输入文档推断。摘要自身length仍拒绝安装，业务残缺JSON/tool_calls不拼接执行；活动恢复链里不再触发自动摘要。Harness的溢出自动重试与“压缩失败仍继续”不直接采用。

## 6. 实现顺序、负责人及验收关口

本轮C2接续按用户指定，由Sol/high主导协议/历史视图/计费边界和独立审核，一个Terra/high子代理实现与Docker自测；覆盖此前将C2计量建议交DeepSeek的安排。DeepSeek保留原M包工作，不与C2共享目录并行写入。用户决定最终验收/合并。

1. 先核对容量/各用途上限，补齐实际请求计量与输出预留，不改变业务执行语义。
2. 定义证据层、保护字段和版本化派生视图；证明现有严格校验仍覆盖原始历史及合法映射。
3. 做有来源的分段读取和同步摘要候选/检查点；在无真实模型的可控替身下覆盖正常/失败。
4. 独立复审通过后再提出有界实际协议探针和收益验证；未确认兼容前保持现行行为/默认不启用自动摘要。

必要验收：

- 计量覆盖中文、reasoning、工具参数/结构；不同用途预留不串用；最终超限零发送。
- 多工具批次不拆分，保留的 reasoning/工具关联符合实际 provider 协议；不完整批次拒绝。
- unknown 写效果、精确 ID、约束及来源跨压缩不丢失；摘要不能导致旧写动作重放。
- 原始日志/账/seal字节不被压缩改写；source失效不能被摘要恢复为原文证据。
- 空/截断/工具调用/不缩小/旧版本摘要均不安装；取消、崩溃及持久化失败有可审计结果。
- 恢复检查点与未压缩路径的关键程序状态一致；机械不变量与人工语义抽查分别报告。
- 统计所有摘要和业务尝试的已知用量、失败、耗时及最终请求长度，不以输入缩短推断总费用必降。

本轮交付只是设计与验收标准；没有新增上述实现或通过结论。下一开发入口为[输出恢复P0–P3](output-recovery.md#7-实现工作包及负责人)：先补本文件的计量/预留前置，再做有界恢复。自动摘要及其真实请求仍是后续独立包，不因输出恢复默认为已经实现或授权。
