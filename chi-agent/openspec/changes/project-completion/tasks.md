# 全项目收尾执行清单

本清单覆盖整个剩余项目；当前全部为计划项，不代表已经启动或授权真实调用。执行依 [design](design.md)，验收依 [契约](specs/project-closeout/spec.md)，唯一状态/权限在 [REVIEW_STATE](../../../reviews/REVIEW_STATE.md)。已启动范围内由 DeepSeek/Gemini 连续推进，不逐项等待 GPT。

## Z0 外部条件与执行启动

- [ ] 刷新主线/PR，保留工作区改动，从最新 main 建实现分支。
- [ ] 取得当前 Kaggle Rules/公告可读正文，关闭概览/旧规则冲突；确认必交清单、时限和报告要求。
- [ ] 复核 Go 的 CHI 用途、十一月资料处理条件、Extra Usage 和实际可用权限；未满足不发相应载荷。
- [ ] 验证 Gemini repo/diff/Docker 能力，用一包离线候选完成试运行审查。
- [ ] 将用户实际启动范围和固定真实额度/用途记录到状态页；未启动项保持暂停。

## Z1 正式入口与配送

- [ ] 核对正式 CLI/适配入口及固定 vendor 参数，明确 bundle/依赖/资源/state/B 的供应责任。
- [ ] 补齐调用方供应或 install 接线，不依赖本机旧源码/卷/账本；不伪造历史或收据。
- [ ] 保持 Agent、官方模拟器、judge 的凭据及文件边界。
- [ ] 独立包完成真实 Harbor 组件/适用 Trial 的离线正常与关键失败路径。
- [ ] Gemini 固定候选独立复验，记录生产供给尚未经过的真实路径。

## Z2 Y 去留

- [ ] 检查来源可见性、case信任、版本/容量、Unicode/字符偏移、窗口和混合列表。
- [ ] 冻结两题 off/shadow 的单变量条件及开销/可靠性观察项。
- [ ] 真实部分获准后按 Z4 清单执行，负结果完整保留。
- [ ] 固定保留纯原型/默认关闭/进一步候选的理由；不擅自生产强制启用。

## Z3 / F0–F7 Agent能力建设

逐项遵循[能力计划](capabilities.md)，每项先固定接口/场景，由DeepSeek实现自测、Gemini独立复审；不能只通过旧角色接线测试就勾完整能力。

### F0 任务家族/能力范围

- [ ] 从公开目录/instruction/工具契约覆盖全部任务家族，形成三角色支持、缺口及依赖矩阵。
- [ ] 每个计划支持家族写正常/缺证/失败分支，未支持项明确披露；不看隐藏答案制定策略。

### F1 业务状态和工作记忆

- [ ] 实现有界run/目标状态、版本和来源关联，区分观察事实、模型推断/计划、缺口与未知写效果。
- [ ] 实现模型读取/提出更新与程序验证，不能覆盖实体绑定/未知状态/新观察。
- [ ] 独立验证错case/旧版本/假来源/超限/持久化失败，原journal和历史不改写。

### F2 角色规划和执行策略

- [ ] 明确三角色公开业务目标、前置依据、动作候选、回读及结束/补证/冲突分支。
- [ ] 实现版本化自有指导/状态接线，不强制所有payer走MD或所有provider提交。
- [ ] 走通计划—行动—观察—更新—结束/未完成，检查患者/副作用、STOP和预算分支。

### F3 规则和证据定位

- [ ] 实现公开目录到相关章节/有界片段的定位、版本/来源及冲突记录流程。
- [ ] 根据实际缺口决定是否新增有界本地关键词/元数据检索；记录采用或不采用依据。
- [ ] 验证同名/错版本/不适用规则、尾部例外、提取失败、跨case与隐藏目录拒绝。

### F4 上下文管理

- [ ] 测量真实输入构成和增长，区分字节/估计/真实token并确定输入预算、输出预留与超限处理。
- [ ] 接通F1/F3的状态/片段组织，原文可回读；实际历史变更不能绕过校验。
- [ ] 核对固定SDK/DeepSeek历史/思考字段续接协议，完成压缩可行性关口和采用决策。
- [ ] 可行时实现版本化同步检查点/替换映射/近期往返；不可行则交付基础组织/预算并明示无自动压缩。
- [ ] 验证缺reasoning/未完成tool批次/旧摘要覆盖/关键否定与未知写丢失；不新增未授权摘要请求。

### F5 完成前核验

- [ ] 从公开目标/工具建立实际状态回读、产物/回执和未解决项记录，分开claim与已核实效果。
- [ ] 实现结束/未完成/未知原因与最终输出一致性，预算有限时如实结束。
- [ ] 验证只写文件/错case/已受理重复提交/缺回执/claim后失败等场景，不使用隐藏期望判成功。

### F6 失败查证和停滞处理

- [ ] 区分参数错误/业务拒绝/读失败/写未知/模型账未知，提供有限纠正及停滞信号。
- [ ] 实现合法同目标只读查证或unknown停止；保留fatal优先，不重复未知写操作。
- [ ] 验证状态延迟/同名不同单/反复无进展/取消清理失败，不增加自动重试或崩溃自动续跑。

### F7 实验与评测工具

- [ ] 补齐配置化实验清单、候选/资源/检查适用性及输出收集，复用原操作者。
- [ ] 为F1–F6形成独立机制对照设计，只执行采用且可独立切换的条件，其他项给出理由/替代证据。
- [ ] 实现全分母/失败/NA/未运行/耗时/费用汇总，隐藏评测与Agent输入隔离。
- [ ] 通用资源选择/公开元数据/角色路径参数化支持新题，固定候选交Gemini关闭阻断。

## Z4 有界真实开发与对照

- [ ] 冻结公开任务、资源、模型/参数、候选和检查适用性；排除暂停题与隐藏材料。
- [ ] 适用旧证据直接复用；清单内最多三角色各一基线。
- [ ] F1–F6机制对照合计最多12次C；单变量不可成立时不宣称单项收益。
- [ ] 最多四次 payer off/shadow 对照，结果不混作未见验证。
- [ ] 问题驱动的最多六次开发回归；修复先离线、复审，再新 attempt。
- [ ] 审计全部失败/未知/结算/终态和 owned 资源；形成选定候选。

## Z5 九题未见集

- [ ] 在看结果前冻结同一候选、每角色三题清单及资源/适用检查，覆盖不同任务家族。
- [ ] 新世界、每题一次；普通业务失败继续，未知/越界/账损坏等依契约停止。
- [ ] 全分母报告工程结果、未评内容和费用；不生成自估 reward。
- [ ] 若改候选，将已看题转开发题，明确新候选的未见验证缺口。

## Z6 干净包和真实正式路径

- [ ] 导出最终包，空状态/日志目录，独立依赖/授权资源供给并记录架构。
- [ ] 无开发账/源码/患者broker依赖，runner 仅有需要的凭据和公开输入。
- [ ] 真实 Harbor 路径每角色最多一次，优先与 Z5 同次运行取证。
- [ ] 核对结果/trajectory/context/失败传播/状态配送及清理；CM 官方/开发环境分别标记。
- [ ] 检查分发 allowlist、凭据和受限材料；未验证正式关键路径不写通过。

## Z7 累计审核与冻结

- [ ] 提供固定候选和 Gemini 独立结果；GPT 可用时完成累计 diff/调用链审查和必要 Docker 抽验。
- [ ] 不把未发生的 GPT 补审写成完成；用户可根据实际独立审核决定冻结。
- [ ] 关闭必需阻断，冻结模型/提示/工具/依赖/入口；后续只修阻断。

## Z8 材料、用户验收与交付

- [ ] 从第一天准备方法/架构/历史证据结构，运行后填真实数据。
- [ ] 完成源码/包与运行手册、外部资源和复现配置。
- [ ] 完成符合已确认规则的 Writeup 和技术报告；最终 PDF 渲染检查。
- [ ] 核对所有实验分母/失败/费用/官方未评与候选一致；规则额外必交项如实补齐。
- [ ] 集中演示正常/失败链并讲解设计取舍；既有学习账本记录，不默认小测。
- [ ] 用户内部验收；固定文件/hash/渠道/正文，取得最终发布/发送授权。
- [ ] 实际交付并保存链接/回执；等待主办方成绩单列，不冒充已评测。
