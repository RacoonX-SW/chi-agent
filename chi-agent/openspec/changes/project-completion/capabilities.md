# 剩余 Agent 能力建设计划

2026-10-31 补充。用户指出首版收尾计划没有展开功能建设；本页把原先笼统的 Z3 拆成 F0–F7。**当前仍是规划，没有实现这些能力，也没有新增模型调用授权。** 它与[整体计划](design.md)的 Z1 正式配送、Z2 Y 去留、Z4–Z8 实验/冻结/交付共同组成完整剩余项目，不是仅增加测试数量。

## 1. 本轮核对到的实际差距

依据是当前自有源码及已有讨论，不把早期提案当成已经承诺或完成的功能：

| 能力 | 现有基础 | 仍需建设/决定 |
| --- | --- | --- |
| 执行循环 | `go_chi_runtime.run_chi()` 使用 SDK 工具循环，附请求预算反馈 | 自有任务状态、角色工作流指导与下一步依据，不只是轮数控制 |
| 任务状态/记忆 | journal 记录请求、工具、claim、账与失败；provider 有患者绑定 | 供模型继续决策的带来源业务进度、未知动作和缺口；账本不能替代任务记忆 |
| 规则与材料获取 | `go_chi_tools` 提供目录和允许路径下的范围读取，已有 PDF reader | 从公开目录定位相关章节/片段、保留版本和冲突；是否增加有界检索须明确决策 |
| 上下文 | 模型收到历史，`ToolContract.validate_history()` 严格匹配已接受完整工具批次 | 输入构成/增长测量、输入预算、重点材料组织；自动摘要/压缩须另验证协议与 SDK 接点 |
| 完成判断 | `local-claim_done` 当前仅调用 `journal.record_claim()` | 基于公开工具回读的完成证据、未解决项与停止原因，不能将 claim 当业务已核验 |
| 失败恢复 | 限额/未知/超时/fatal/取消/清理已有工程控制 | 对业务工具结果未知的保守查证、进度停滞识别与有限重规划；不自动重发写操作 |
| 评测改进 | 原终态、部分确定性检查、逐阶段开发实验 | 三角色一致的实验清单/检查适用性/失败分类/对照和完整分母汇总 |
| 参赛交付 | 独立包、Harbor 组件/合成演练和历史安装证据 | 正式供给/真实启动、最终独立复现及材料，仍由 Z1/Z6/Z8 完成 |

源码核对入口：`scripts/go_chi_runtime.py`、`scripts/go_chi_tools.py`、`scripts/go_chi_contract.py`、`scripts/go_chi_guard.py`。历史设计依据见[执行循环讨论](../../../docs/agent-loop-discussion-2026-10-21.md)、[上下文研究](../../../docs/codex-context-compaction-study-2026-10-21.md)及[开发讨论](../../../docs/development-discussion-2026-10-21.md)。这些历史提案没有自动变成冻结实现规格；下面对每项给出建设任务和独立验收。

## 2. 功能建设的共同边界

F1–F7 作为本计划启动后的能力工作包，DeepSeek 先固定最小接口和场景，Gemini 审查后在范围内实施和返工，不等 GPT 逐模块批示。正常内部设计选择可自行决定；新增付费请求 purpose、提高运行上限、更换提供方、修改官方世界/评分器或生产强制临床决策仍超出本计划。

新增行为使用明确的版本化自有配置/工具契约和候选身份，保留可复现的原参考路径供基线比较。不能把原 `official.SYSTEM_PROMPT`/完整历史校验删掉后假称旧行为不变；改变系统提示、输入组织、工具集合或 history 契约时，必须维护 guard、manifest、身份/B、记录和对应测试，不用宽泛放行代替兼容。

原业务真值来自本次可见公开 instruction/工具结果，模型给出的计划、推断和总结保持 model_report 属性。工具错误不能提升为事实，隐藏 expectations/solution/judge 输入不进入 Agent 状态/检索/提示，所有真实运行自主完成。

## 3. F0：任务类型与能力清单，避免按三道题定义三角色

**交付**：根据固定公开目录、instruction 类型和工具契约，建立 provider/payer/cm 的任务类型—必要能力—工具/外部依赖—可观察完成证据矩阵。只读公开字段，不用带预期答案的 tasks.jsonl 为运行时路由或调参。

至少区分初次准备/提交、补证或后续办理、payer不同处理分支、CM沟通/跟进/结案等实际存在的任务家族；这些名称是核对维度，具体家族与工具须读源码/公开任务后填写，不能凭此虚构支持。记录“当前支持/需要改动/未支持/依赖官方服务”，不只列三个角色名字。

对每个计划支持的家族定义一条正常与一条失败/缺证/拒绝分支；无法在本周支持的家族明示缺口，用户若决定裁剪要在冻结材料说明，不能默默从完整目标删掉。

**验收**：Gemini 对照公开输入与实际调用入口，确认矩阵不是把同一条成功路径复制到全部角色。矩阵放执行阶段唯一报告，不另造重复状态文件。

## 4. F1：带来源的任务状态与工作记忆

**问题**：运行账记录了“调用过什么”，并不等于模型有稳定可用的“现在知道什么、还差什么、哪个操作结果未知”。

**最小接口**：一个有界的每 run/目标任务状态对象，以及模型读取/提出更新的方式。字段覆盖角色/目标实体、实际观察的 ID、观察事实与来源、模型推断/计划、缺口/冲突、已执行动作及结果未知项、最新核实业务状态、下一步候选。字段名/大小/工具 schema 在实现前冻结。

程序只从可信元数据登记已观察事实/操作结果；模型可提交带来源的解释和计划，但不能凭文字修改 patient/case 绑定、清除未知操作或覆盖较新观察。每次更新关联 run、版本、来源 call_id/hash；外部业务系统状态始终比本地摘要更权威。旧版本保留，不在多个目标/case/run之间串用。

**失败验收**：错 case、未观察来源、无效 hash、旧版本覆盖新事实、未来结果、模型把推断填为事实、未知写操作被摘要改成失败/成功、状态超限和持久化失败。旧journal/claim/账目原字节不因增加状态而重写。

**交付结果**：Agent 可在同次运行继续决策时读取状态并回读原文，不声称跨中断自动恢复/跨任务长期记忆已实现。进程重启恢复涉及额外身份/副作用处理时，另列限制。

## 5. F2：三角色任务规划与业务阶段指导

**问题**：模型会调用工具，不证明会组织完整业务任务；此前 Z3 把这一层误写得过于接近普通修补。

**交付**：从 F0 支持范围与公开规则提取三角色的任务计划/阶段指导，包含当前目标、前置证据、合法动作候选、执行后回读、缺证/冲突/升级/结束分支。采用自有提示/本地状态和工具指导的最小形式，不预先要求 LangGraph 或多 Agent。

程序控制接口/权限/已观察事实，模型解释适用规则并决定下一动作。不能要求所有 payer 必经 MD、所有缺项必挂起、所有 provider 必提交或 CM 一定按同一话术/固定轮数结束。阶段指导不是照着隐藏答案强制状态机。

**场景**：材料充分、合法补证、相互矛盾的公开规则、工具参数错误、状态已经完成、目标不明确、可选分支、消息/患者 STOP、预算将尽。连续走通“计划—行动—观察—更新计划—完成/未完成”，不能只验证模型生成了一份好看的计划。

**验收**：Gemini 独立检查所有实际新增指令的来源和分支反例；在合成真实 SDK/MCP 边界验证工具链，再进入额度内对照。把模型生成正确建议和实际产生正确业务效果分别记录。

## 6. F3：公开规则与证据的定位、读取和核对

**交付**：目录/角色入口→相关章节定位→有界原文读取→来源/版本/适用范围记录→冲突/缺项处理。先复用既有 reader/目录/公开索引；若仍反复迷路或漏条款，再增加本地有界关键词/元数据检索。必须留下是否需要新增检索的依据和决策，不能把“能读文件”当作已完成规则使用能力。

若增加检索：限定已授权 handbook/本run公开workspace，结果含路径、片段位置、hash/版本及截断标记；限定 query/文件数/结果数/总字节，拒绝链接和越界路径。索引和片段按原资料授权留本地，不上传派生全文索引；不引入外网搜题、向量库或全手册灌入作为默认方案。

模型仍负责区分政策条件与建议、事实与推断、适用范围和版本；程序只保证取到的来源与片段可追溯。Y 的引用校验作为可选机械层，不能代替语义正确性。

**失败验收**：相近关键词的无关政策、角色/服务不适用、旧/新版本冲突、同名文件、否定条件/例外在尾部、PDF空页或提取失败、超大结果、未授权/隐藏目录、跨 case 注入。定位失败可报告未找到，不能编造依据或扩大查询权限。

## 7. F4：上下文预算、组织与压缩可行性

**必须交付的基础能力**：

1. 记录实际请求中任务/工具定义/材料/历史/reasoning 的构成与增长；字节/字符/估计 token/服务返回 token 分列，不把某种计数冒充精确 tokenizer。
2. 在已核对的模型/endpoint能力和实际 SDK 接点下制定输入预算、输出预留、超限处置；不能用50轮或文档的1M窗口代替实际验证。
3. 结合 F1/F3，减少重复整份资料输入，支持相关片段回读和有来源状态；上下文里实际有的信息与磁盘档案分开。若改变实际历史，进入下面的版本化协议设计，不能隐蔽替换工具结果。

**独立的压缩可行性关口**：当前 `validate_history()` 要求完整已接受工具批次逐项匹配，不能简单删旧消息。先证明固定 SDK/DeepSeek 路径能在完成的工具批次边界合法组织新窗口，确认必须重放的 reasoning_content、消息/工具关联与续接约束；本地历史研究不是本轮 API 兼容证据。

若可行，再实现同步、版本化的受控检查点：任务约束/工具契约/受保护状态/近期完整往返/相关原文共同构成新输入，保存原历史、替换映射/hash和前缀版本；拒绝过期摘要覆盖新后缀。模型摘要是可选候选，不自动覆盖结构化真值。

若需要额外收费摘要调用，先另明确 purpose/核算/请求上限，当前额度提案不含独立摘要请求；优先在已有主循环记录结构化进度或确定性整理，不暗增第二模型。不能合法压缩时，完成可测的输入预算/组织/超限停止能力，并明确“自动压缩未实现/不采用”及理由。不得以未实测协议宣布整项上下文能力已完成。

**失败验收**：未完成tool批次、缺 reasoning、重复tool id、丢否定条件/关键日期/目标ID、把未知写变失败、陈旧检查点覆盖较新受理结果、原文不可回读、预算或快照写入失败。不能因恢复历史再次执行已发生写操作。

## 8. F5：结束前业务回读与完成证据

**问题**：当前 claim 只是模型声明。现有开发操作者的事后终态捕获，不能直接冒充运行时 Agent 已自主核验完成。

**交付**：在合法公开工具范围内，为 F0 支持的任务目标建立完成证据记录：实际目标实体、最新状态查询/回执、所需产物与其来源、未解决项、停止原因。目标解释由模型提供并标 model_report；程序核对可机械验证的实体/来源/动作效果，不使用隐藏 expectations 推导成功条件。

区分模型声明完成、公开效果已核实、限额/缺证未完成、结果未知；最终文本与状态记录一致。对已有明确待处理工具或未知写效果的结束请求返回具体未决原因，由模型在剩余预算内查证或如实未完成；不强迫无限补调用，不把合法的补证/挂起/拒绝当失败。

**场景**：状态已受理但模型想再提交、只写文件未发起业务动作、产物存在但错 case、缺回执/无法回读、CM已满足停止条件、部分完成后限额耗尽、claim后最终回复生成失败。完成证据不等于官方或临床 verdict。

默认启用这类行为属于明确自有运行策略变更，必须连同 guard/claim后准入规则、最终输出和候选身份一起审，不将“原claim继续原样”与“新核验已生效”混说。

## 9. F6：业务失败查证、停滞识别与有限重规划

**交付**：把参数可纠正、合法业务拒绝、读失败、写效果未知、模型/用量未知、资源损坏分开。普通参数错误给出工具契约范围的纠正信息；连续重复无进展的相同查询/拒绝提供有依据的停滞信号，让模型改计划或结束，阈值和身份在实现前冻结。

对写效果未知，只允许通过同一目标的公开只读查询查证；查询看到旧状态不自动证明未执行。无法证明时保留 unknown，禁止重发写操作。当前账目/模型结果未知会阻断的路径保持优先，不能为查业务效果绕开 fatal/账门禁；如在单次运行无法合法继续，交付可审计未完成结果。

不增加自动 HTTP/SDK/MCP重试、后台轮询、换模型、换账根或重开同attempt。用户另选的一次新attempt不是原请求自动重试；其历史关联与预算照常保留。进程崩溃后的自动业务续跑不作为本周默认实现，除非另取得副作用与恢复安全的充分规格/证据。

**失败验收**：写已执行但响应丢失、状态延迟、同名不同申请、重复动作、读错误被当材料缺失、反复查同一内容消耗全部预算、fatal期间仍派新读/写、资源清理失败。停止是合法结果，不能为“跑通”吞掉错误。

## 10. F7：可复用实验与评测改进工具

**交付**：独立于被测 Agent 的实验清单与结果汇总，绑定版本、任务/角色/资源、模型/模拟器条件、变更开关、请求限制、attempt、适用检查及日志。可以复用原操作者和检查器，补必要的配置化/汇总，不重造框架。

按六个机制（F1–F6）准备至少一组有明确假设的开发对照设计；只对实际采用且可单独切换的机制执行相关单变量对照，其他机制交清楚的合成/兼容证据和不采用原因。不得把六项一起改后的结果叫六项分别有效。某机制确无现有问题证据时不得为了功能数强行启用。

结果分别列运行接线、业务可观察效果、适用确定性检查、内容未评、官方未评；实现自动收集可获得的计数/耗时/费用与失败分类，缺字段留空并说明。受限资料和隐藏检查输入仅在隔离评测侧，不进入 Agent 的状态/检索/提示；看过结果的题转开发集。

**验收**：混合成功/失败/未运行/NA的数据有正确分母，缺日志不记通过，跳过不计通过，旧未结算累计不补零，不跨模型/模拟器/候选混算；失败历史不可被“最新一次”覆盖。用自造记录验证汇总行为，再按 Z4/Z5 实际实验填结果。

## 11. 依赖、交付顺序与规模

F0先明确目标家族；F1提供状态基础；F2/F3使用该基础；F4依赖状态/来源和真实历史协议核对；F5/F6使用任务目标、最新观察及未知动作记录；F7从第一天准备清单，随每项接入产出数据。Z1正式供应可穿插离线准备，功能候选固定后必须重验最终包，不能只验旧包。

每项先冻结接口/不变量/开关和正常/失败场景，DeepSeek实现、自测、固定候选；Gemini独立审查/相关Docker复验后继续下一项。相互依赖的步骤可在一个实现PR内连续做，但每项保留独立候选和证据；不等每个函数/测试单独审批。

工作量不再用首版24次C覆盖全部新功能。修订的**待审**额度在[整体计划](design.md#11-真实运行额度提案尚未生效)统一维护，包含功能机制对照、更多回归和每角色三题未见集；不是开发额度充足就无限试题。11/6前无法达到必需能力标准时，应报告延期/明确裁剪方案，由用户选择，不把未实现功能藏进“收口完成”。
