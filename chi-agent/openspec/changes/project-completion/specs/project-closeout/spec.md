# 项目收尾行为契约

本契约定义可验收行为，不授予新的真实调用、官方判分或发布权限。执行细节见 [design](../../design.md)，实际许可和状态只见 REVIEW_STATE。

## 需求：功能建设不能用接线和打包代替

执行[能力计划](../../capabilities.md)的F0–F7，分别交任务范围、状态记忆、角色规划、规则定位、上下文、完成核验、失败查证和实验工具。每项必须有最小接口/正常和失败行为/实际独立检查；自动压缩或新增检索可按可行性与必要性决定，但不采用须给原因和已交付的基础能力，不得把整项默默删去。

### 场景：任务状态带来源更新

模型提出进度或计划更新时，程序按当前run/case、版本和已观察来源检查；观察事实与推断分列。较旧更新不得覆盖较新受理结果，未知写操作不能被改写为失败或成功，原始证据可回读。

### 场景：三角色存在合法不同分支

角色指导允许按公开依据选择提交/补证/升级/停止等适用路径，不要求所有payer必经MD、不预设任何题的批准/拒绝结果。不能仅因单一代表题跑通就声称支持同角色全部任务家族。

### 场景：规则定位结果不适用或冲突

保留来源/版本/片段与适用范围，模型说明不确定性；未找到依据时不编造条款，不读取隐藏评分材料。检索只在允许的公开资料范围，索引不扩大分发权限。

### 场景：上下文达到输入界限

在发送前采用已验证的预算与合法组织方式；字符/字节不冒充精确token。需要换历史时必须满足版本化协议/思考字段/完整工具批次条件，保留原历史和替换依据；无法合法处理则记录原因停止，不能删消息绕过原完整历史校验。

### 场景：模型声明完成但效果未核实

结束记录区分claim、公开效果已核实、未完成和unknown。仍有待处理工具或未知写效果时给出具体未决项，预算内合法查证或如实结束；不把存在文件/claim/正常退出等同业务成功。

### 场景：写操作响应丢失

同目标公开只读查询可用于查证，旧状态不足以证明没执行；无法确定就保留unknown，不重发写操作。模型结果/token未知或fatal门禁优先，不能为继续查证绕过原准入。

### 场景：对照评价多个能力

仅对独立切换且其余条件一致的机制形成单项比较；六项一起修改后的结果不能分摊成六项收益。未采用机制交可行性/必要性判断，全部失败、跳过和未运行记录进入正确分母。

## 需求：连续执行不依赖 GPT 日常在线

当用户启动整套有界工作且当前包依赖满足时，DeepSeek 可在范围内实现、Docker 自测和返工，Gemini 可独立审查/复验；通过后继续下一已授权包，无需逐步等 GPT。模型不同不自动产生独立证据；同一工作区一个实现写入者。

### 场景：独立复验通过

给定固定候选和隔离环境，Gemini 自己检查 diff/调用代码并执行相关 Docker 检查，记录环境、命令、退出码和结果，可标对应范围“Gemini 独立复验通过”；GPT 后续未执行的部分仍待审。

### 场景：只有日志访问

Gemini 只读实现者报告或日志时，只能形成代码/日志审阅结论，不能标自己运行过 Docker；不依赖该缺口的工作继续。

## 需求：最终运行来自可配送包

外部调用方通过明确的公开输入、角色 MCP、日志和非秘密身份配置启动包；包、依赖、授权手册及运行状态的供应责任明确，不依赖开发机器或旧账。普通离线组件通过与真实模型/正式环境通过分别记录。

### 场景：干净目录实际启动

仅供应可分发包、固定依赖及调用方获准资源，从新状态目录运行真实适配路径；产生可对应 instruction、输出、用量和进程结果的日志/trajectory/context，并确认本轮 owned 资源清理。

### 场景：调用方未供应依赖或身份

在读取/发送模型载荷前清楚拒绝或按明确安装流程补齐；不悄悄借用源码 checkout、本机卷、旧 B 或开发账，不将安装 no-op 写成安装通过。

### 场景：失败或硬中断

非零/缺返回码、日志缺损、未知用量、取消或资源清理失败均留下原错误与终态/清理记录；未确认清理时不得宣称无残留，也不能把运行失败填成官方 0 分。

## 需求：三角色行为及模拟器条件分开验证

provider/payer/cm 的公开输入、实体、工具和状态契约各自检查；正常结束、业务终态、确定性检查、内容评审和官方 reward 分列。未知角色/错角色 MCP 在发送前拒绝。

### 场景：开发 CM 模拟器

显式使用开发 Go 患者得到的结果必须标该条件，包外 broker/能力文件/账目不进入生产包；官方默认患者和 judge 不被覆盖。无官方模拟器真实证据时不得宣称该路径已实测兼容。

## 需求：Y 的机械边界不能替代语义判断

来源仅来自本次模型实际观察的公开材料；case/版本/容量/片段语义沿 Y 已审契约。引用有效仍为 semantic_assessment=not_performed，不由影子结果自动批准/拒绝或阻断业务。

### 场景：缺少收益证据

对照未完成、可靠性不足或开销/收益不明确时，可保持纯原型/默认关闭并完成项目交付；报告不声称收益已证实。不能为了按期交付扩大引用有效的含义。

## 需求：有限实验可追溯且不污染未见集

每次调用的任务/配置/候选/资源/attempt 先固定；失败、已知用量和旧未结算完整保留。仅执行用户实际同意的额度，未知结果/token 停止同账真实准入，不阻止不依赖它的离线工作。

### 场景：看过未见题后修改代码

已运行/分析题转为已见开发材料；新候选在这些题上的重跑只能标开发回归，新候选独立未见覆盖另行说明。不能换掉困难题或只选成功记录进入分母。

### 场景：服务条件变化

跨月隐私、用途许可或端点条件不再明确时，暂停相应业务资料外发并继续合成/源码工作；不自动换提供方、启用余额额外用量或假装 coding 请求。

## 需求：完结须有材料和实际交付证据

当前比赛 Rules/公告决定必交项；来源冲突未解决时保留未确认，不靠旧文档宣布参赛条件满足。内部目标日不替代官方期限。

### 场景：工程完成但规则/正式依赖仍阻断

只标已完成的工程/材料及明确缺口，不能标“全项目参赛交付完成”。如规则要求全量公开官方评测，未经运行不得补 reward，所需 judge/模拟器资源单独列明。

### 场景：用户批准后的正式交付

固定文件/hash、实际接收渠道与正文，取得用户最终决定，执行发布/私有交付并保留链接/回执后才标交付完成。官方私有成绩未公布时保持待评测，不预写效果结论。

## 需求：可靠性治理遵守已讨论范围

2026-11-02新增的负责人和M/C工作包按[设计第15节](../../design.md#15-可靠性治理与分阶段重构)及用户实际启动范围执行、固定候选并独立复验，状态只查 REVIEW_STATE；不因计划入库修改历史账、生成新B或新增模型请求。C2输入/输出契约及连续离线P0–P3见[输出实施包](../../output-recovery.md)，实际实施结果以唯一审核状态和阶段报告为准。

### 场景：模块归属与旧代码复用

模块地图必须对照内层PACKAGE_FILES、外层release及实际调用关系，识别局部复用；不能按名称将整个旧模块判废或让开发操作者/患者替代器自动进包。当前只补地图和检查，物理目录迁移保持待评估。

### 场景：局部导入或配置漂移

包依赖检查覆盖函数内导入、可选外部依赖和未知动态导入；隔离导出包不读取源码checkout来补缺。配置一致性检查使用真实profile/身份链，故意修改错误字段/类型/上限时须拒绝，不通过打桩核心预检掩盖差异。相同数字但不同用途分别建模，安全硬边界不因集中化删除。

### 场景：生成资源manifest

生成器按明确角色/schema/visibility分类，拒绝链接/越界/缺文件，输出确定性且原子地不覆盖既有或竞争创建的产物；原preflight必须检查三个角色的正常结果，任务world_id必须与所选主world匹配。隐藏服务初始化文件与Agent可见输入分离，自动扫描不扩大资料权限。预检/提交失败不破坏旧产物，不以两次exists检查冒充原子不覆盖。

### 场景：诊断cause升级

保留原对外安全分类及停止/结算语义，cause采用有限安全结构且不含原异常/载荷/Key。旧证据可验证，新schema/坏字段明确校验，不重写旧证据或宽松忽略未知字段。包源码/证据契约变化按实际身份变化处理。

### 场景：未知请求与后继state

无Console匹配记录不自动证明未发送；报告须区分无记录、已知发送前失败、在途未知和经证据/授权处置。任何后继state/evaluation必须说明来源和准入依据，不能以保留旧pending但更换路径规避未知限制，也不能未核实就认定已有违规。

### 场景：只读检查与交付结论

工具/报告检查不读取Key、发送模型、启动世界或修改原账；损坏资料显式失败、缺字段不补零、skip/环境错误不计通过。纯文档检查通过只证明文档交付，不证明任何运行修复、真实账审计、临床结果或官方分数。

## 需求：输入压缩须是可追溯的合法派生视图

详细设计及实施关口见[输入方案](../../input-context.md)。先覆盖实际请求计量与各用途输出预留，再验证版本化压缩视图；不得放宽现有完整历史校验来接受任意模型摘要。保护状态、原始证据/未知/费用和来源权限继续由程序维护。

### 场景：预算不足或单次新输入过大

中文、reasoning、工具schema与参数及适用结构均进入实际请求测量。不能把启发式估算当精确tokenizer；请求仍超限、容量未知或单次输入无法合法分段时明确停止，不先发往摘要模型试错，不静默丢用户要求。

### 场景：摘要候选无效或历史已变化

只选闭合批次且保留近期完整工具往返；空/截断/工具调用/不缩小/坏来源/保护字段冲突/旧版本摘要不安装。原证据与账保留，摘要不能把未知写效果改成成功/失败或触发旧写重放。检查点持久化失败不得标可恢复。

### 场景：来源经过压缩或失效

摘要、原文曾被观察和当前可引用原文分别标识；失效来源不能因进入摘要再次current。临床/保单资料不统一首尾截取，能按合法来源回读原文，不引入隐藏expectations/world-only资料。

### 场景：摘要请求和输出恢复

额外摘要请求须另定用途/额度与同账关联，失败或未采用仍记实际用量，未知仍阻断。输入设计不授权溢出自动重试或模型回退；残缺业务tool_calls/JSON不拼接执行，摘要自身截断不采用。输出恢复按下面独立契约；协议兼容未验证前默认不自动摘要。

## 需求：已知length按显式策略有界恢复

行为及首版数值以[输出恢复契约](../../output-recovery.md)为准。只有完整合法length响应已可信结算、原批次零执行、闭合历史无未知、时间/共享额度/输入预算允许时，程序才能消耗一次性continuation许可。默认关闭，任意“继续”消息或手工purpose不能触发。

### 场景：部分文字与残缺工具批次

无工具时精确保留同一原响应的未完成content/reasoning并追加版本化固定指令；有工具时整批零accept/dispatch，从最后合法闭合历史重新生成，不拼参数、不伪造tool结果。新批次仍走原整批/实体/角色/路径/claim门禁；明确已完成写按canonical工具/参数指纹拒绝恢复直接重放，已拒绝零执行调用不冒充完成写。

### 场景：次数、未知与失败

每链最多一次、每CHI运行最多两次追加，main/confirmation/continuation共享50，单次上限保持8192/32768等原用途值。再次length保留两笔用量并停止；未知结果/token、取消、网络、超限或持久化失败不触发恢复。先持久消耗许可再reserve，一次性绑定，重启不自动续发，不重启Runner或重置截止。

### 场景：严格历史与旧证据

完整原始证据、SDK接受的闭合历史和临时wire派生视图分别维护。许可关联父main请求/响应hash、结算、历史版本/hash、固定指令版本和精确派生view；旧run不补字段，启用新run/permit/关联严格校验类型、字段与一对一轮次。inspect/replay只读，旧请求/seal字节不改；不以忽略未知字段兼容。wire与许可决策trace分开，SDK逻辑步不代替物理HTTP或原账累计。

### 场景：离线验收及真实边界

唯一Terra/high实现者停止写入后，主代理从固定候选独立检查调用链、真实SDK+MockTransport、故障断点及无源码补依赖的导出包。合成通过不证明Go真实协议、临床正确或官方成绩；新候选的新B/有界协议探针另行授权，旧基线不冒充新版本验证。
