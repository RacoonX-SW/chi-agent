# 项目收尾行为契约

本契约定义可验收行为，不授予新的真实调用、官方判分或发布权限。执行细节见 [design](../../design.md)，实际许可和状态只见 REVIEW_STATE。

## 需求：连续执行不依赖 GPT 日常在线

当用户启动整套有界工作且当前包依赖满足时，DeepSeek 可在范围内实现、Docker 自测和返工，Gemini 可独立审查/复验；通过后继续下一已授权包，无需逐步等 GPT。模型不同不自动产生独立证据；同一工作区一个实现写入者。

### 场景：独立复验通过

给定固定候选和隔离环境，Gemini 自己检查 diff/调用代码并执行相关 Docker 检查，记录环境、命令、退出码和结果，可标对应范围“Gemini 独立复验通过”；GPT 后续未执行的部分仍待审。

### 场景：只有日志访问

Gemini 只读实现者报告或日志时，只能形成代码/日志审阅结论，不能标自己运行过 Docker；不依赖该缺口的工作继续。

## 需求：最终运行来自可配送包

外部调用方通过明确的公开输入、角色 MCP、日志和非秘密身份配置启动包；包、依赖、授权手册及运行状态的供应责任明确，不依赖开发机器或旧账。普通离线组件通过与真实模型/正式环境通过分别记录。

### 场景：干净目录实际启动

仅供应可分发包、固定依赖及调用方获准资源，从新状态目录运行真实适配路径；产生可对应 instruction、输出、用量和进程结果的日志/trajectory/context，并确认本轮 owned 资源清理。

### 场景：调用方未供应依赖或身份

在读取/发送模型载荷前清楚拒绝或按明确安装流程补齐；不悄悄借用源码 checkout、本机卷、旧 B 或开发账，不将安装 no-op 写成安装通过。

### 场景：失败或硬中断

非零/缺返回码、日志缺损、未知用量、取消或资源清理失败均留下原错误与终态/清理记录；未确认清理时不得宣称无残留，也不能把运行失败填成官方 0 分。

## 需求：三角色行为及模拟器条件分开验证

provider/payer/cm 的公开输入、实体、工具和状态契约各自检查；正常结束、业务终态、确定性检查、内容评审和官方 reward 分列。未知角色/错角色 MCP 在发送前拒绝。

### 场景：开发 CM 模拟器

显式使用开发 Go 患者得到的结果必须标该条件，包外 broker/能力文件/账目不进入生产包；官方默认患者和 judge 不被覆盖。无官方模拟器真实证据时不得宣称该路径已实测兼容。

## 需求：Y 的机械边界不能替代语义判断

来源仅来自本次模型实际观察的公开材料；case/版本/容量/片段语义沿 Y 已审契约。引用有效仍为 semantic_assessment=not_performed，不由影子结果自动批准/拒绝或阻断业务。

### 场景：缺少收益证据

对照未完成、可靠性不足或开销/收益不明确时，可保持纯原型/默认关闭并完成项目交付；报告不声称收益已证实。不能为了按期交付扩大引用有效的含义。

## 需求：有限实验可追溯且不污染未见集

每次调用的任务/配置/候选/资源/attempt 先固定；失败、已知用量和旧未结算完整保留。仅执行用户实际同意的额度，未知结果/token 停止同账真实准入，不阻止不依赖它的离线工作。

### 场景：看过未见题后修改代码

已运行/分析题转为已见开发材料；新候选在这些题上的重跑只能标开发回归，新候选独立未见覆盖另行说明。不能换掉困难题或只选成功记录进入分母。

### 场景：服务条件变化

跨月隐私、用途许可或端点条件不再明确时，暂停相应业务资料外发并继续合成/源码工作；不自动换提供方、启用余额额外用量或假装 coding 请求。

## 需求：完结须有材料和实际交付证据

当前比赛 Rules/公告决定必交项；来源冲突未解决时保留未确认，不靠旧文档宣布参赛条件满足。内部目标日不替代官方期限。

### 场景：工程完成但规则/正式依赖仍阻断

只标已完成的工程/材料及明确缺口，不能标“全项目参赛交付完成”。如规则要求全量公开官方评测，未经运行不得补 reward，所需 judge/模拟器资源单独列明。

### 场景：用户批准后的正式交付

固定文件/hash、实际接收渠道与正文，取得用户最终决定，执行发布/私有交付并保留链接/回执后才标交付完成。官方私有成绩未公布时保持待评测，不预写效果结论。
