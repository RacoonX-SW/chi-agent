# CHI Agent 仓库整理

## Why

六题开发基线已经有可核对的阶段结果，GitHub 首页仍从旧工具探针阶段开始介绍。项目源码和工具藏在一层目录里，文件名也保留了开发阶段编号，读者需要先了解历史才能找到当前入口。

## What Changes

- 将 Python 项目、Docker 配置、测试和 OpenSpec 提到 Git 根目录。根 README 展示项目用途、六题开发基线和 Docker 快速开始。结果保留各自的程序包身份、证据链接与 `official_reward=null`。
- 保留两份运行手册、当前协作和审核入口以及仍在使用的规格。阶段报告、学习历史和已被替代的方案通过[整理前的固定提交](https://github.com/xsw932187210-cell/chi-agent/tree/fdff6cff629a6c7ccd0de0d37bdc18d92ff8a57d)查阅。
- **BREAKING（源码检出路径）** 将正式模块迁到 `src/chi_agent/`，开发操作、早期实验和维护工具分到 `scripts/` 的三个子目录。使用按职责命名的模块和按操作命名的命令。迁移对照覆盖全部 72 个原脚本。
- **BREAKING（新包的内部成员路径）** 两种导出包使用版本化布局。Go 与兼容评测保留原有启动路径、参数和 Harbor 导入入口。校验器按版本识别固定的旧清单与新清单，继续绑定实际包字节。
- 本变更范围限于目录、文档、导入、容器挂载、导出布局和离线验证。运行策略、任务结果、账本处置、真实模型调用、正式评分与竞赛提交沿用现行规格和各自的授权。

## Capabilities

### New Capabilities

- `repository-distribution` — 源码检出与导出程序包的可发现入口、版本兼容和历史结果追溯。

### Modified Capabilities

本变更新增仓库与包布局契约。现有运行和配送行为继续由对应规格约束。

## Impact

- 影响仓库的 Python 导入、测试入口、Docker 构建上下文和绑定挂载，以及两种 bundle 的成员映射。依赖和工具链使用当前锁定版本。
- 现有本地凭据、手册、数据、vendor 与运行产物留在原位置。迁移验证使用隔离检出、临时输出和所需的只读依赖挂载。
- 计划基线为 `fdff6cff629a6c7ccd0de0d37bdc18d92ff8a57d`。提案在 `codex/repository-layout` 审核，最终实现由面向 `main` 的 PR 交付并由用户合并。
