## 本轮确认与规则复核

- 用户正确判断：更换参赛模型主要调整模型/API 接入配置，无需重写官方病例数据库。这只证明该职责边界已经能解释，不代表已经实际完成接口适配。
- 已通过实际浏览器正文复核 [Kaggle Rules](https://www.kaggle.com/competitions/chi-bench/rules) 第 9、10、11 条：公开成绩可选，不要求跑完公开任务；每个符合条件的队伍会获私有评测，主办方承担私有评测 API 费用。提交仍须包含 Writeup、私有可运行程序包和报告，材料或程序不可运行可影响参赛资格。
- 官方本地判分依赖 Anthropic；规则第 10 条同时指定了 Claude 患者模拟器。因此，缺少该 API 不只影响本地评分，部分依赖模型的模拟对话也可能无法按官方配置实测。实际受影响工具路径须逐项核对，不把所有 MCP 工具都视为必然免费可用。
- 用户当前只有 DeepSeek 约 25 元人民币余额、Gemini 免费及约 10 美元额度，均为用户报告，未发请求验证。当前不要求追加充值。现有余额不等于已授权全部消耗。

## 怎样继续验证

| 验证层 | 计划检查什么 | Anthropic 缺失的影响 | 允许得出的结论 |
| --- | --- | --- | --- |
| 离线检查 | 配置解析、参数、超时/错误处理、日志、凭据不泄漏 | 不依赖模型 | 对应代码路径通过离线检查 |
| 官方工具接入 | 初始化公开任务环境，连接角色 MCP，取得实时 schema，检查允许的读写与回读 | 普通业务路径可先验证；对话模拟等路径须单独检查依赖 | 已观察到的工具与状态变化有效 |
| 真实 Agent 开发运行，无官方评分 | 用已选模型驱动一次任务，保存调用、结果、错误、停止原因与文件；结束后对照公开任务要求分析 | 参赛模型可用不等于所有模拟对话可用；依赖缺口如实记录 | 该运行路径已经实测；官方 reward 仍未知 |
| 官方完整判分 | 原版 judge 与规定的模拟器、判分配置 | 当前暂缓本地执行；最终由主办方私有评测 | 只有真实官方 verdict 才能报告官方 reward 或 pass@1 |

无评分执行仍需程序在开始后自主完成；人工分析只发生在运行前后。自检检查公开任务要求、合法接口、已产生的产物和可访问业务状态，不读取隐藏 expectations、答案或 verifier-only 文件，也不能用自检替代官方判分。

当前核对的 `cb experiment run` CLI、`ExperimentConfig` 和 `experiment/runner.py::_build_harbor_command` 未见直接关闭 judge 的选项。恢复实现时，先验证独立开发入口是否能复用官方环境和 runner 而不调判分器，或固定版本实际支持的其他非评分入口。未验证前不提供可复制运行的命令，不捏造 `--skip-judge` 等参数，不修改正式评分器来制造通过。

补充源码发现：`task_runtime.collect_all_verifier_checks(..., include_semantic_judge=False)` 的阶段校验分支可返回部分确定性结果而不启动 workspace judge。这是待集成的函数入口，不等于已有 CLI 选项；运行于独立验证进程，隐藏评分资料不能回流给 Agent。所得结果只报告部分检查，完整官方 reward 仍为 null。

若独立入口尚未接通，可以先交付离线和工具连接部分，并准确列出未验证项。无评分结果放入本项目自己的开发记录，`official_reward` 为 null，说明判分未运行；不伪造官方 `scorecard.json` 或声称完成正式基线。

2026-10-21 实际复核 DeepSeek 官方 [模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)、[Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/) 和 [Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)：`deepseek-flash` 当前为 Flash-1017，支持工具调用和思考模式。API 名是服务商别名，不是不可变化的模型快照；真实运行记录请求标识、返回模型标识、运行日期和当时的版本说明，不伪造不可变锁定。

思考模式的历史字段要求仍是接入重点：实际选定 SDK 必须完整保留 provider 所需字段及工具关联。非思考模式可用来定位兼容问题，但它通过不证明思考配置通过；有差异就分别记录。Chat Completions 文档的 `max_tokens` 支持显式限制输出，默认思考模式输出额度较大，因此本次拟明确限制生成量。来源：[API 说明](https://api-docs.deepseek.com/api/create-chat-completion/)。不因为文档支持就声称该参考 runner 已正确传参。

接入验收补充：用户已正确判断普通聊天成功不能代表 Agent 接入通过。若工具结果回传后的模型请求报 400，要先确认错误来自哪个请求；工具本身可能已执行成功。因此记录要区分“工具有没有实际执行/效果是否核实”和“后续模型请求是否接受”，整体闭环仍标为未通过，不能把所有失败笼统记作工具失败，更不能自动重放已执行的业务写操作。Agent 的自主动作循环不等同于模型的“思考模式”开关；非思考模式也可以调用工具，但不替代当前候选思考配置的验收。

恢复实施后按三个检查点推进：

| 检查点 | 要做什么 | 通过所需的证据 |
| --- | --- | --- |
| A：官方环境与工具 | 补齐任务依赖，初始化环境，连接医院侧 MCP，取得实时 schema，做允许的只读查询 | 实际工具发现/调用记录、返回结构、环境身份；计划不调用模型，只选择已核实不触发模型的路径，启动依赖缺口单列 |
| B：模型与工具完整往返 | 在候选 harness/runner 中用合成小工具验证模型产生请求、程序执行、结果配对回传、模型继续；思考模式须跨至少两次工具往返 | 实际请求设置、关联 ID、后续响应和用量；只报告协议接入结果，不当成医疗任务轨迹 |
| C：单任务自主执行 | 从干净初始状态执行选定任务一次，接入真实角色工具和必要手册，结束后分析轨迹与业务回读 | 任务/模型/模式/版本、真实轨迹、关键效果与缺口、停止原因、用量来源；`official_reward=null` |

检查点 A 的调用即使是查询也可能留下审计，因此 C 必须使用独立干净初始状态，不能沿用调试后已经改变的任务世界。B 的合成数据不进入 C 的病例上下文，不把合成工具验证写成正式试跑。

预算管理建议：先给 B 预留最多 0.5 元，剩余至多 4.5 元用于 C；这是 5 元内的初始分配建议。已确认的总额不能被两阶段分别重复使用。按当前 Flash 高峰未命中输入 2 元/百万 token、输出 8 元/百万 token 做保守预估；真实用量、价格日期和估算/账单来源分别记录。价格会变，恢复付费运行前重新核对。每个新请求前根据累计用量、下一请求输入与最大输出预留费用，余量不足就停止，不无限重试或自动再跑一次任务。外层超时与本地估算不能证明精确账单封顶；当前尚未验证服务商账户侧硬限额。

第一阶段验收的是接入、执行与证据是否可信。C 若因预算结束而未完成，必须记为预算停止/任务未完成；若业务选择不满足要求，也如实报告，不能只因程序退出就判任务成功。确定性诊断若适用，在独立验证侧运行；隐藏评分资料不进入 Agent 输入，完整官方 reward 仍未知。

首轮暂不加入自动历史摘要、后台压缩、新业务阶段控制器或多 Agent 编排。先记录输入长度和失败，再把必要改进写为后续独立变更。模型调用适配、预算与轨迹记录属于本轮接入所需的最小工程；若必须超出当前参考 runner 的扩展能力，先报告具体差异并调整设计。
