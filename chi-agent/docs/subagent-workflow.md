# 实现子代理与主代理独立审核

**全项目收尾专项（2026-10-31）**：用户启动[连续执行计划](../openspec/changes/project-completion/design.md)后，该范围由 DeepSeek 协调/实现、Gemini 独立审查与实际可执行的 Docker 复验，GPT 做规划及后续累计审核，覆盖下文默认模型分工。普通规格内返工及已授权工作包衔接不等 GPT；Gemini 只读日志不能写独立执行通过。当前仅交付计划，不派实现代理、不恢复真实调用。用户可依据实际 Gemini 结论决定合并，具体 Git 权限仍依 GitHub 工作流和状态页，不因角色变更扩大。

更新：2026-10-27。用户明确将默认实现子代理改为 GPT-6.1 Terra：模型显式 `gpt-6.1-terra`、推理强度沿用 `high`；主代理负责规格、协调、独立审核、教学和 GitHub。此前 Luna（包括 D0/A 双代理）的实际分工保留在历史报告，不改写成新模型。开发子代理与 DeepSeek 参赛运行时分开，此调整不更改用户全局模型配置。

模型标识已核对 [OpenAI 官方模型说明](https://learn.chatgpt.com/docs/models#choose-a-model-2)；本会话派发接口提供该模型。文档约定与实际派发结果分别记录，未成功启动时不能声称已使用 Terra，也不能静默替换。

## 默认闭环

1. 主代理核对当前授权与 Git，从最新 origin/main 建任务分支，给出有界目标、必读材料、允许修改路径、验收行为及停止条件。
2. 一个 GPT-6.1 Terra / high 实现并在 Docker 中自测，返回改动文件、入口、实际命令/退出结果、证据路径和未验证项；不要复制整段聊天或另写重复交接报告。
3. 停止写入并固定候选后，主代理读差异和必要调用代码，独立检查；有证据的问题交回同一代理修复，再复验受影响行为。
4. 通过后由主代理显式暂存、提交、推送并创建 PR，用户审核决定合并。操作细节只维护在 [GitHub 工作流](github-workflow.md)。

普通问答、纯文档和 Git 管理由主代理直接完成。实现代理不自行切分支、全量暂存、丢弃他人改动、push 或创建下级代理。模型不可用时报告，不能静默替换。

## 何时增加第二个代理

仅在已授权开发任务中，工作确实可独立并行且预期收益足够时使用。启用前，主代理说明第二个代理的具体任务、交付、文件/资源所有权和收益；用户已给出的范围内可执行，无需为常规分工重复确认，扩大范围仍需明确授权。

共享目录只有一个实现写入者；只读分析可并行。两个实现者确需同时写入时，先隔离 worktree/checkout 与测试结果目录，再合并并独立复验。两个代理反复等待接力、同时改共享文件、重复阅读上下文或单纯等待下载，都不是固定增加代理的理由。不得递归扩增或自行超过两个。

## 权限与证据

子代理继承当前工具和沙箱权限，角色描述不创造安全隔离。安装、下载、测试、调试均遵循 [Docker 工作流](docker-workflow.md)，不修改用户全局模型设置。

主代理审核保留独立性，不因子代理自测通过就验收。详细证据只放一份阶段报告，当前已审/已通过身份只汇总到 [REVIEW_STATE](../reviews/REVIEW_STATE.md)。开发子代理用量与参赛运行时预算分别记录；不保证代理减少就必然节省某个比例的 token 或时间。
