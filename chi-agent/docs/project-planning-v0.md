## 目标与当前建议

当前首要目标：按官方要求完成可复现的竞赛 Agent 和最终提交，在官方私有任务上接受评测。简历成果整理放在真实实现和竞赛记录形成之后。

起步调试范围：医院侧申请准备，从新转诊出发，核对病例与规则、发现缺失材料、准备申请，并正确选择提交或补证。这个范围只用于尽快理解任务和建立真实基线；正式竞赛还评价保险方利用管理与照护管理任务，整体排名按私有三领域结果计算。

起步调试角色：医院侧负责整理病例和事前授权申请的工作人员。其他角色的覆盖方式在理解官方任务后决定；当前不制定独立业务产品的前端或用户操作方案。

建议核心链路：接收一个公开模拟转诊案例 → 读取病例证据 → 按适用规则核对材料 → 调用医院侧允许的工具准备记录与表单 → 材料充分时提交、材料不足时保留补证记录 → 输出可追踪的执行与结果摘要。

公开样例已支持这一业务边界，但完整病例世界和实时工具契约尚未运行核对。目前不假定具体表单字段、枚举值、工具签名和状态机。

## 资料前后的 OpenSpec 工作

### 资料未获得时

先写目标、用户、输入/输出边界、范围、失败处理原则、交付阶段和验收方法。将未知字段标为待确认，不编造 MCP 工具或业务状态。

### 获得样例与必要访问后

阅读少量有代表性的公开任务，定位所需手册章节；核对实际工具契约、业务状态变化、角色权限、公开评分规则、模型接口和成本。无需先通读整份手册。

手册下载和使用遵循实际授权；受限原文、任务产物和衍生输出的公开范围需确认。不能把资料下载完成等同于业务规格已确认。

### 冻结首版范围后

形成用户确认的 proposal、design、行为 specs 和分批 tasks，再交给执行器实现。实现中发现事实差异时，更新对应变更并保留原因，而不是让执行器自行扩大或弱化验收。

## 候选阶段

1. **规划与资料校准**：确认流程和 MVP，核对访问/接口，冻结首版规格（当前阶段）。
2. **可信基线**：先验收离线入口，再在前提就绪后运行一个官方任务，取得真实耗时和可用资源记录。
3. **自有 Agent MVP**：实现选定流程及必要的证据和工具控制，覆盖正常与失败路径。
4. **固定任务对照**：同模型、同任务集比较基线与自己的策略，分别记录成功数、失败原因、耗时和可信成本。
5. **作品交付**：整理复现说明、演示和允许公开的结果，再决定简历表达和正式竞赛提交范围。

本周范围在资料校准和首次真实成本测量后再细化，不提前承诺分数提升或名次。
