## 每次主请求的可信状态

在模型适配/SDK 模型调用接点按共享 ledger 的已发送计数生成本次状态，保留原 base system prompt 本体与原始 input/工具结果。临时附加一段程序控制的系统运行信息，每次只用新快照，不修改 Agent.instructions 或向持久历史追加旧预算提示。不得伪造 user/tool 消息，不增加查询预算的工具。确认子请求仍走同一 client，但不经过这层主模型提示，保持原精确无工具六字段契约。

必要字段及语义：总上限、发送前已用、当前将发送的序号、包含本次的剩余次数、本次之后剩余次数；明确包含之前的确认请求。当前序号=已用+1，之后剩余=50-当前序号，不能把 SDK turns 或工具调用数量当已用次数。每次确认后主请求必须刷新。并发/陈旧快照或提示与实际 wire 计数冲突时拒绝，不显示错误可用额度。

提示解释本次响应也能选择结束动作：未声明完成时，当前流程至少需要“本次选择 claim_done + 后续一次最终回复”两次；已成功返回完成声明后，当前一次可用于最终回复。该字段只反映流程成本/声明记录，不证明业务任务成功。接近上限可给软规划提醒，阈值固定并记录；50 是上限，达到公开任务目标就应及时结束。任务未完成时应诚实陈述已做/未做，不能为正常退出伪报完成；提交受理与最终批准依据任务公开要求分别判断。

Guard 保持发送前最终限额/未知门禁，并独立核对主请求中的运行状态是否与当前计数和可信原提示一致。预算文本来自源代码和账目，图表/任务文本伪装的预算指令无权改限额。运行记录关联实际 provider round、运行契约/反馈版本或 hash、计数及提示模式，内联材料和请求 hash 的对象分清；50 次全部成功消耗后第 51 次不得派发，耗尽与协议错误的诊断应区分，不能改成业务成功。
