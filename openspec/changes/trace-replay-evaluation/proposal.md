# CHI Agent 离线 Trace/Replay 评测提案

## Why

`inspect-history` 能用原始证据复核历史账本和上下文投影，现有实验工具能汇总固定条件下的记录。增加可执行的回放用例后，维护者可以用同一组模型响应和工具回执验证新版执行规则，并定位首个不符合预期的步骤。

## What Changes

- 提供仓库内的离线回放入口，在 Docker/Python 3.12 中通过现有运行接缝将固定模型响应和模拟 MCP 回执送入实际 Agent 执行链路。
- 固定四个合成场景，覆盖截断工具批次零派发、写入超时且效果未知、缺少写后回查时拒绝完成声明，以及有效写后回查后接受完成声明。
- 输出可比较的 JSON 报告，包含用例集身份、运行源码身份、计划与通过数、实际工具派发和完成声明的观测值。每个失败用例定位到首个轨迹差异或失败断言。
- 以验收报告中实际运行的用例与检查为后续简历表述的依据。

## Capabilities

### New Capabilities

- **`trace-replay-evaluation`** — 固定合成轨迹、执行离线回放并对照候选报告。

### Modified Capabilities

无。

## Impact

- 提案以 GitHub `main` 的 `1e26a76d54da9c811ed12201f81f7092c8b19d29`（PR #102）为基线。本地隔离检出的已跟踪文件与该基线一致。
- 交付面为 `scripts/tools/`、合成用例与回归测试，以及 README 中的简短运行入口。回放复用 `run_chi`、`ChiJournal`、实际 SDK Runner 和 MCP 桥接逻辑的现有接口。
- 首版验证执行规则、轨迹对齐和可复验性。真实任务成功率、模型决策质量、线上延迟、TTFT、费用收益和官方评分需要各自的独立运行证据。
