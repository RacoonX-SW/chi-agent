# Provider 新转诊提交前门禁设计

## Context

`TaskState` 目前从工具名称推断 Provider 阶段与完成证据。上游 `docs.create_submission_bundle` 会写入提交产物，并根据必填项、文件类别和表单完整性改变案件状态。应在这个写入之前确定业务分支。

## Goals / Non-Goals

让 Go Provider 在新转诊中使用有依据的服务地点、先判断再打包，并从真实同案回执核对完成。沿用当前模型循环、患者绑定和 MCP 工具。历史运行、既有案件的跟进路径、Payer 与 CM 按各自现有入口和规则处理。真实模型复验另行决定。

## Decisions

1. **作用范围**。使用 Go `chi-context-v3` 的 Provider 状态。服务地点检查适用于该路径的 `cases.create_from_order`。建案回执通过患者、医嘱、服务和地点核验后绑定目标案件。已有目标时拒绝重复建案。已存在案件的提交、补件和后续流程沿用现行路径。两个入口都验证原有的身份、工具和未知写入门禁。
2. **地点证据**。在现有本地状态更新入口记录拟填地点和来源。优先核对目标患者医嘱的结构化实际执行地点。文字依据引用已读取的公开任务、医嘱、病历或预约原文，明确关联所申请服务的执行场所。文档标题、开单机构、既往门诊、规则列举的可选地点及模型自己生成的表单不能单独证明地点。程序核对已交付页面和当前病历版本，文字证据按原文完整语句判断，保留否定、条件和地点限定语。地点值和所引医嘱的服务编码必须与建案参数相符。证据缺失、冲突或无法可靠提取时允许继续读取，必填值无法确定时报告缺口。
3. **证据判断和决定**。本地状态更新记录适用公开规则、与目标服务相关的病例依据、判断和具体理由。判断区分支持提交、缺证和应停止。校验来源类型、作用域、原文和版本。程序核验这些形式条件与动作一致性，证据充分性的语义判断由 Agent 依据公开材料作出。决定使用同案 `auth.finalize_provider_determination`。已校验参数中的 `final_action`、成功回执中的 `case.id` 与 `case.status` 一起形成决定证据，回执缺少实际动作字段时从已验证的请求参数取值。该工具返回的 `ready_to_submit` 表示决定完成且尚需打包提交。
4. **派发和意图锚点**。在现有串行派发锁内检查门禁。已成功记录 `submit_pa` 才能建包，并且只有同案、确切的完整包才可提交。缺证、停止、未判断、错案、无效或未知写入状态均阻断相应操作。决定所依据的材料发生实质变化时须重新核对，成功改写表单或上传证据后须重新打包。锚点从程序观察的目标、证据和决定推进，先呈现证据判断再呈现打包步骤。拒绝记录在现有工具轨迹中，并给出下一步可补的内容。
5. **完成核验**。保留现有必需读写、claim 和未知写入规则。根据同案公开返回的结构化状态、有效决定回执和该分支的产物判定完成。提交分支核对真正的提交写入、对应提交包及之后同案回查，兼容模拟器已经进入的合法下游状态。补证和停止分支从决定后 `cases.get_case` 核对 `docs_needed` 或 `closed`，并查同案没有提交包或提交写入。把回查的证据 ID 留在现有完成记录。保留旧版状态、日志、导出包和账本的读法。
6. **复验**。上一轮失败轨迹用于识别错误顺序。用自主合成输入经实际 SDK 和模拟 MCP 回放，避免引入评审期望、固定地点、任务 ID 特判、protected handbook 内容、额外模型请求或 vendor 改动。

## Risks / Trade-offs

- t016 已交付材料没有明确支持医院门诊这一执行地点。地点拦截可能让真实题更早报告缺证。测试分别证明拒绝无据地点，以及地点有公开依据时可完成补证分支。
- 独立复验前 PR #104 和 #105 已进入 `origin/main`。本变更接到该主线，在同一候选上验证分页、超时策略和提交门禁。
