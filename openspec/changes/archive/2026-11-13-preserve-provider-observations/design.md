# Provider 观察证据分页设计

## Context

`MCPBridge.invoke` 先从完整响应更新 `PatientBinding`，再把裁剪结果交给模型。身份确认的名单校验要求本轮已交付名单与已观察名单一致。对于病历，旧页固定取 12,000 个字符，通用裁剪可能改写分页对象的正文。确认时要求正文按页覆盖原病历。

## Goals / Non-Goals

让 Provider 能完整观察有界的候选名单和所需病历，保留现有证据、调用额度和身份写入门禁。变更限于 Provider Go 的观察交付与覆盖校验。语义确认继续使用原指令、完整候选集、相似候选的已观察病历和已有确认请求。

## Decisions

1. 合格的完整无筛选搜索用精简名单的第 0 页作为模型可见结果。名单含同一版本的全部候选标识及核对字段。保留患者标识、姓名、出生日期和性别，临床区分事实从原病历或相应订单读取。用原名单 SHA-256、起止范围、总数及下一页偏移标识页面。需要翻页时，Provider 专用本地读工具按名单版本和偏移交付。普通搜索结果仍走现有裁剪。
2. 复用病历读取工具。每页用实际 JSON 序列化后的字符和 UTF-8 字节计量，在现有 8,192 码点和 32 KiB 内选择有进展的原文区间，页内提供原文版本、起始偏移、总长度与下一页偏移。将原始 MCP 结果与派生的模型可见页分别按现有证据路径记录，已定长的页直接进入工具历史。
3. 确认从实际已交付的工具消息查找证据。只采纳与当前名单或病历原文版本对应、能从原观察确定性重算的完整页。连续覆盖可以跨模型请求累计，名单或病历内容改变时旧版本的页不参加覆盖。回查最早观察时需使用实际发送的模型消息视图。后续历史可以继续投影已经送达的页。
4. 恢复与历史验证仍按各次记录的来源及发送视图校验。已保存的完整名单或病历工具结果按原有规则识别。保持旧的病历工具调用参数可用。
5. 模型按工具说明调用分页。确认反馈给出尚缺的相似候选病历，完成覆盖后才进入现有语义确认。语义确认结果仍需分区覆盖全部候选、通过原文引用校验，并由绑定门禁检查患者和医嘱归属。

## Risks / Trade-offs

- 分页缩小单条工具返回，整次请求的上下文预算继续生效。把首次页面和下一偏移直接交付，减少重复搜索。
- 八条历史轨迹只用于离线定位和回归。动态补齐证据后可验证确认输入准备完成，完整业务结果取决于新一次自主运行。
- 选择 Provider t016 做一次真实开发复验。它在先前同批的三次尝试均复现患者确认阻塞，并有完整可比资源。Go 新包先做一次 Coding B，最多 6 次请求。任务运行共享 50 次主请求与身份确认额度，确认最多 2 次，主请求输出上限 16,384。采用当前已批准的 DeepSeek V4.1 Flash 路线，记录费用，保留未知请求和终态，遇到传输或准入阻断时留存本次证据。
- Provider 修复分支从最新主线开始。若 PR #104 在复验时仍待合并，单独构建叠加已批准的 300 秒读取和 360 秒总 I/O 的开发候选，记录两项变更的 Git 身份。Provider 修复 PR 只提交本变更。
