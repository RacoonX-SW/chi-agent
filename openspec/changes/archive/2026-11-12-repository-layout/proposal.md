# CHI Agent 仓库整理

## Why

开发运行已覆盖 Provider、Payer 和 CM，最近一组六题基线也已完成。GitHub 首页仍从旧工具探针阶段开始介绍，源码、阶段材料和验证记录混在项目外层目录中，读者需要先了解历史才能找到成果和当前入口。

## What Changes

- 将 Python 项目、Docker 配置、测试和 OpenSpec 提到 Git 根目录。根 README 展示项目用途、Docker 快速开始、累计开发覆盖和最新六题基线。按任务 ID 去重，已确认 75 个公开任务中至少 20 个有真实运行记录，官方评分字段为 `null`。
- `docs/` 仅保留两份简明运行手册。现行协作规则集中在 `AGENTS.md`，当前审核状态和成果证据索引集中在 OpenSpec。学习材料、逐轮验证记录、过程报告和已被替代的方案移出默认分支文件树，从[整理前的固定提交](https://github.com/xsw932187210-cell/chi-agent/tree/fdff6cff629a6c7ccd0de0d37bdc18d92ff8a57d)查阅。
- 常规离线验证使用一个维护命令，开发镜像内统一用 pytest 收集测试，另跑 controller 专项和两种包的隔离预检。重排验证的详细结果集中写入交付 PR。
- **BREAKING（源码检出路径）** 将正式模块迁到 `src/chi_agent/`，开发操作、早期实验和维护工具分到 `scripts/` 的三个子目录。使用按职责命名的模块和按操作命名的命令。迁移对照覆盖全部 72 个原脚本。
- **BREAKING（新包的内部成员路径）** 两种导出包使用版本化布局。Go 与兼容评测保留原有启动路径、参数和 Harbor 导入入口。校验器按版本识别固定的旧清单与新清单，继续绑定实际包字节。
- 本变更范围限于目录、文档、导入、容器挂载、导出布局和离线验证。运行策略、任务结果、账本处置、真实模型调用、正式评分与竞赛提交沿用现行规格和各自的授权。

## Capabilities

### New Capabilities

- `repository-distribution` — 源码检出与导出程序包的可发现入口、版本兼容和历史结果追溯。

### Modified Capabilities

本变更新增仓库与包布局契约。现有运行和配送行为继续由对应规格约束。

## Impact

- 影响仓库的 Python 导入、测试入口、Docker 构建上下文和绑定挂载，以及两种 bundle 的成员映射。依赖和工具链使用当前锁定版本。
- 现有本地凭据、手册、数据、vendor 与运行产物留在原位置。迁移验证使用隔离检出、临时输出和所需的只读依赖挂载。
- 计划基线为 `fdff6cff629a6c7ccd0de0d37bdc18d92ff8a57d`。提案在 `codex/repository-layout` 审核，最终实现由面向 `main` 的 PR 交付并由用户合并。
