# CHI-Bench 全项目收尾计划

建立：2026-10-31（Asia/Shanghai）。用户要求扩大规划，让 DeepSeek/Gemini 连续推进整个项目的剩余工作，下周完成。**本轮交付规划和协作文件，不开始功能编码或项目模型调用。** 当前授权、实际候选和进度只见 [REVIEW_STATE](../../REVIEW_STATE.md)。

## 目标

以 **11/6 冻结候选、11/8 完成内部验收及交付材料** 为目标，覆盖正式启动与配送、三角色工程能力、有限真实开发实验、未见任务检查、独立复现、技术报告和最终交付。日期是内部目标，不是官方期限或完成保证。开发和材料完结与主办方返回私有成绩分开。

不将“已经做过很多阶段”换算成已完成 1/3，也不承诺追加固定 2/3 代码即可完赛；剩余工作按下面的可检查交付项收束。用户追问后修订：首版 Z3 过度概括了功能建设，不能把其余工作主要理解为测试/打包。现补[F0–F7能力计划](capabilities.md)，覆盖任务类型、状态记忆、角色规划、规则定位、上下文、完成核验、业务失败处理及实验工具。

## 范围

- [设计与连续执行计划](design.md)：Z0–Z8 工作包、依赖、日程、实验额度提案和裁剪顺序。
- [剩余 Agent 能力建设](capabilities.md)：每项的当前源码缺口、最小接口、实现任务、反例和独立验收；不将早期讨论误当已完成能力。

- [任务清单](tasks.md)：按依赖顺序执行；实现者可在已启动的工作包内自行拆解和返工。
- 复用已有 Go runner、Harbor 适配、账目/预算/身份、开发操作者和 Y 原型，不重造核心框架。
- DeepSeek 担任执行协调和唯一实现写入者，Gemini 独立审查与有条件的 Docker 复验，GPT 在规划及后续累计审核时介入，用户最终验收/合并。

## 启动方式

用户对本计划的讨论、规划 PR 的合并，不自动等于所有真实运行已获准。执行启动时，将**整套离线工作**及**一份固定的真实运行额度/用途清单**一次性确认到 REVIEW_STATE；在此范围内不逐包等待 GPT。尚未启动时可继续核对规格、准备差异和材料，不对外发送项目载荷。

新的付费/真实阶段只在依赖满足后启用。项目级新请求、开发代理对话额度、最终官方评测是不同账户/用途；不把“开发额度充足”当作 CHI 非编码用途、十一月隐私条件、Claude 判分或外部发布授权。

## 不纳入本轮必做项

新网页产品、全新编排框架、通用医疗规则引擎、训练模型、生产强制证据审核、无明确瓶颈的并发、1M 上下文/长缓存探索。全量 75 题/官方 audit packet 是否强制，以 Z0 复核的当前竞赛规则为准，不能仅沿用旧文档或概览搜索结果。
