## Why

当前已取得手册并理解一个公开任务的静态输入与工具说明，但完整运行环境、实时工具契约、模型接口和实际执行仍未验证。先取得可复查的单任务开发执行证据，再据此修复工程问题；本地官方判分按用户取舍暂缓，不能把无评分执行或官方示例描述成任务已通过或自己的业务实现成果。

## What Changes

- 提供容器内安装、下载、检查与测试入口、可复现开发镜像及受控构建上下文，不要求宿主机安装项目 Python/uv/Node 依赖；官方任务仍按固定环境执行。
- 提供不调用模型的就绪检查，明确 Python、uv、Docker、访问与配置缺口。
- 固定官方仓库提交、数据版本和实际镜像身份，给出可复现的安装与运行入口。
- 区分官方静态任务说明、实时工具契约和实际运行轨迹，不把示意流程当作已发生的执行记录。
- 在必要访问、预算和非评分入口验证后，用内置 Agent 在一个公开任务上收集真实开发执行轨迹；部分模拟对话依赖分别核查。
- 本地官方判分当前暂缓，未来配置齐全时另行执行并保留原始结果。
- 保留运行配置、退出状态、官方判分来源与资源记录；缺失数据显式为空。
- 提供正常、缺依赖和运行失败情况下的离线验证及交接报告。
- 验证实际 runner 中连续的模型/工具往返，记录精确模式与实际限制；累计核算首轮运行预算，未恢复执行前不发起模型请求。
- 既有 B 合成探针准备了候选请求格式、至少两次工具往返、逐请求预算门禁和失败记录；本轮以它为起点补充独立 SDK/官方 runner 接入层，真实模型传输继续暂停。
- 在 B 离线证据基础上开发 C 单题执行控制：纯计划、持久单次尝试保护、共享预算入场检查、合成环境生命周期和失败/清理记录；真实无评分执行依赖保持显式未完成。
- 增加隔离于 vendor 的模型/runner 接入层；通过固定真实 SDK 与上游 runner、注入无网络 HTTP 响应及合成工具，验证实际序列化、历史、预算和零重试。准备直接 runner 的无评分路径，CLI 继续拒绝真实执行。
- 为后续真实 B 准备独立 provider profile 与无网络预检，令可注入的通用请求边界消费明确价格/输入预留和累计账目；用 mock HTTP 复验同一边界，不创建生产账本或读取凭据，也不因配置齐全而解除执行暂停。

## Capabilities

### New Capabilities

- `benchmark-readiness`: 检查依赖、运行官方单任务基线并形成可核验的本地证据。

### Modified Capabilities

无；这是初始变更。

## Impact

预计新增项目清单、检查/运行脚本、离线测试和基线报告模板。下载的上游仓库、数据、手册及原始结果放入忽略目录。真实 API 调用的数量和配置必须有明确上限。

本轮不实现自己的 Agent、不跑全量 75 任务、不改变官方判分、不提交比赛结果，也不实现 RepoPilot 的任何功能。

## Completion Boundary

“离线实现完成”“真实开发执行已验证、未评分”和“官方判分已验证”是三个独立状态。手册访问、模型凭据或运行环境未就绪时，只能验收已有证据的部分；没有官方 verdict 时 reward 为 null，不得声称任务通过。官方判分暂缓不妨碍交付已验证的开发接入，但正式评分项保持未完成。
