# F0–F3 Agent 能力建设：任务范围、状态记忆、角色规划与资料定位

建立：2026-10-31（Asia/Shanghai）。状态与授权只查 [审核接续状态](../../REVIEW_STATE.md)。本变更只覆盖第一组能力包；F4–F7、Z1–Z8 仍按全项目收尾计划推进。

## 为什么现在做

当前 `run_chi()` 已经能完成三角色真实工具循环、患者绑定、请求预算和终态捕获，但模型仍主要依靠原始工具结果和长历史自行组织业务：

- 没有“当前知道什么、还差什么、哪个写操作结果未知”的独立业务状态；运行账只记录调用，不构成任务记忆。
- 不同角色、不同任务家族的合法分支没有被显式表达，容易出现 payer 一律送 MD、provider 一律提交、CM 固定话术等错误。
- 规则/材料只能整文件读取或列目录，定位相关章节依赖模型逐文件试读，缺少有界检索和来源记录。
- `local-claim_done` 仍只是模型声明；没有把“已写业务动作但未回读”与“已完成”分开。

这些是能力缺口，不是接线或打包问题。全项目计划把 Z3 拆成 F0–F7；本变更先交付 F0–F3，作为 F4–F6 的基础。

## 范围

- **F0**：从公开任务索引、角色工具目录和公开 instruction 建立任务家族—能力—工具—完成证据—支持状态矩阵，明确未支持家族。
- **F1**：有界的每 run 业务状态 `chi-task-state-v1`，区分程序观察、模型事实/计划、缺口和未知写效果；带来源、版本、目标实体校验。
- **F2**：版本化三角色阶段指导 `chi-role-guidance-v1`，覆盖正常/补证/冲突/停止分支，不强制单一业务结局。
- **F3**：限定公开资料范围的有界定位 `local-fs-search`，返回路径、行号/字节位置、hash、截断标记；原文仍由既有 `local-fs-read` 回读。

## 非范围

- 不实现 F4 自动压缩/上下文重写、F5 完整完成核验、F6 停滞重规划（本变更只提供 F5/F6 需要的状态与未知记录接口）。
- 不改变官方 `SYSTEM_PROMPT`、官方世界、评分器、MCP 工具集合或隐藏资料边界。
- 不新增模型/提供方、付费请求 purpose、真实调用次数或判分权限。
- 不做向量库、外网检索、把手册/数据索引上传或写入参赛包。
- 不承诺跨进程/跨 run 长期记忆；状态随本次 run 的日志目录保留。

## 与全项目计划的关系

全项目收尾计划及 F0–F7 能力计划目前位于未合并的规划分支（PR31）。本变更从最新 `origin/main` 建立独立分支，自带契约与 F0 矩阵，不依赖该规划分支先合并；两处若表述冲突，以本变更冻结的接口和 [REVIEW_STATE](../../REVIEW_STATE.md) 的授权为准。

## 执行分工

- DeepSeek V4.1 Flash 负责规格细化、唯一实现写入、Docker 自测和返工。
- 外部订阅 Gemini 在实现前审阅本契约、实现后独立读差异/调用代码并执行必要 Docker 复验；只读聊天/日志时只能记审阅。
- 用户决定合并、真实运行与对外交付；GPT 不在日常推进的必经关口。
