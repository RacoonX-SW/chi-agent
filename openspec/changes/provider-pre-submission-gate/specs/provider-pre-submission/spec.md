# Provider pre-submission

## Purpose

使 Go Provider 能在真实写入前区分服务地点与开单地点，并按有依据的决定完成新转诊。

## ADDED Requirements

### Requirement: 建案前核验服务实际执行地点

Go Provider SHALL 在派发新建案件前核对所填服务地点与本轮已观察的合法来源。缺少或冲突的地点依据 SHALL 保持待核对。

#### Scenario: 医嘱或病例明确记载执行地点

- **GIVEN** 目标患者已经绑定且对应服务的执行地点在已观察的公开来源中明确可核对。
- **WHEN** Agent 引用该来源并以一致的地点枚举建案。
- **THEN** 地点校验允许继续既有派发流程。

#### Scenario: 病历只有开单地点或引文无效

- **WHEN** Agent 只引用开单机构、旧就诊地点、规则枚举、自己生成的材料、未观察的来源或错患者记录，或者建案参数与有效依据不一致。
- **THEN** 程序拒绝建案并保留可诊断的证据缺口。

### Requirement: 先记录有依据的决定再打包或提交

本轮新建的目标案件 SHALL 先记录与公开规则和病例证据相联的判断，再通过现有 MCP 写入确定的 Provider 决定。打包和提交 SHALL 按已验证的决定、案件和当前有效产物放行。

#### Scenario: 完整性信号出现但应补证或关案

- **GIVEN** 表单或病例返回技术就绪标记，Agent 的判断和决定指向补证或关案。
- **WHEN** Agent 请求创建提交包或提交授权。
- **THEN** 对应工具调用被拒绝且没有到达 MCP 服务。同案决定记录和补证或关案的只读回查可继续。

#### Scenario: 有依据的正常提交

- **GIVEN** 有来源的判断支持提交，且记录 `submit_pa` 的同案写入返回一致。
- **WHEN** Agent 创建该案的完整提交包并以同一个包提交。
- **THEN** 相关操作在既有身份与写入检查通过后派发。缺少决定、回执无效、错案、资料失效、包缺失或包未就绪时拒绝相应操作。

### Requirement: 用分支终态证据核对完成

新转诊的完成声明 SHALL 根据实际的同案决定、终态工具回执和之后的结构化回查进行校验。程序 SHALL 检查该分支的提交产物，不能用模型状态文字或表单完整性代替。

#### Scenario: 补证决定及待补材料回查

- **WHEN** 已记录 `gather_more_evidence` 且决定后的同案读回是 `docs_needed`，期间没有同案提交包或提交动作。
- **THEN** 在其它原有条件满足时，允许完成声明。

#### Scenario: 停止决定及关案回查

- **WHEN** 已记录 `do_not_submit` 且决定后的同案读回是 `closed`，期间没有同案提交包或提交动作。
- **THEN** 在其它原有条件满足时，允许完成声明。

#### Scenario: 正常提交与有效回查

- **WHEN** 已记录 `submit_pa` 且实际提交了该案对应的包，之后读回一致的同案提交产物和状态。
- **THEN** 在其它原有条件满足时，允许完成声明。

#### Scenario: 状态、产物或来源和分支不符

- **WHEN** 只有模型声明或表单就绪，决定返回无效，缺少写后读回，终态或产物和分支不一致，或存在未决写入。
- **THEN** 程序拒绝完成声明并报告可追溯的原因。
