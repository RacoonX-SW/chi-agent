## 一轮变更

1. 核对 Git/当前任务及已有 PR，fetch origin 并确认实际主线。保留未提交改动，不 reset 或全量暂存；在写入前从最新 origin/main 新建任务分支。
2. 在该分支实现、自测并停止写入，固定候选提交；没有 commit 时保留可复核 patch/文件摘要，不能只报 HEAD。子代理沿用主代理分配的分支，不自行切换或操作 Git 存储。
3. 主代理比较基线/候选差异，再按影响补读入口、调用者、配置及测试；在 Docker 内做必要独立检查。权限、依赖、持久化或接口改变时扩大检查范围，不默认重读全仓库或全量日志，也不因审核重复付费 trial。
4. 用一份阶段报告记录候选、关键改动、实际命令/结果、证据路径和限制；在 REVIEW_STATE 保留短索引。纯文档/低影响改动可用 PR 说明记录检查，不另建验收报告；不写模仿文档内容的测试。
5. 检查上传范围，显式 `git add -- <文件清单>`、commit、推送任务分支并创建 PR。PR 说明最终行为、验证和限制；未完成实现可用 draft。若自动创建受阻，先完成分支推送，明确阻塞与 compare 链接，不能声称已创建。
6. 用户提出意见时继续在原任务分支修复、复验和推送。用户合并后核对实际远端结果，下一独立任务从最新 origin/main 新建分支；不往已合并分支追加新任务，不将未合并分支当作主线。

`commit` 保存本地版本，`push` 更新指定远端分支，只有用户合并才进入 main；这些操作与代码验收分别记录。每个创建的 PR 都附加到当前聊天；任务结束后不设置后台轮询或自动唤醒。

## 上传边界

不上传 `.env`、令牌、私钥、下载手册、数据、vendor checkout、本地环境、`.coordination/`、真实轨迹或含受限内容的产物。忽略规则不替代暂存清单检查，也不会自动移除已跟踪文件。私有仓库仍是外部上传。

原始日志留在忽略目录，报告只记录允许披露的元数据、版本和结果；GitHub 不作为 Kaggle 自动提交入口。阶段通过只对应实际固定代码及所注明范围，文档/存储提交不能冒充新实现验收。
